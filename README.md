# 선박 도장 AI Co-Pilot (SprayXR)

**[메인 페이지](http://keti-xr-lab.iptime.org:58000/home) · [API 문서](http://keti-xr-lab.iptime.org:58000/docs) · [DB뷰어](http://keti-xr-lab.iptime.org:58000/admin) · [3D 모션뷰어](http://keti-xr-lab.iptime.org:58000/motion-viewer)**

선박 도장·블라스팅 훈련 시뮬레이터와 연동해 작업자에게 피드백과 훈련 결과를 제공하는 AI Co-Pilot 서버입니다.
전문가 기준 데이터와 훈련 기록을 비교하고 작업 자세와 도장 경로를 시각화합니다. 훈련 중 발생하는 질문에도 답변합니다.

소스 버전은 **v3.15.1**입니다. [버전별 변경 이력](CHANGELOG.md)과 [GitHub 릴리스](https://github.com/KETI88-DEV/sprayxr-copilot-server/releases)에서 변경 내용을 확인할 수 있습니다. 소스 게시와 서버 배포는 별도로 진행하며, 각 운영 서버의 반영 버전과 상태는 Home에서 확인합니다.

DB뷰어 학습 데이터의 **시험자료 확인(구축 검증)**에서 등록 건수와 기존 JSON·원천·실제 모션 재생 검증 결과를 확인하고 증빙 목록을 내려받을 수 있습니다. 기록을 선택하면 전체·Zone 통계와 CSV→JSON 정보화 과정을 살펴볼 수 있습니다. 관리자만 검사를 실행하며 조회는 공개입니다. 페이지 접근 기록은 별도 관리자 화면에서 확인합니다.

v3.12 소스의 Home은 등록 학습자료 현황과 업데이트, 주요 화면의 진입점을 모았습니다. AI 질문에서는 분야별 질문 예시를 골라 입력하고 학습자료의 근거 문단을 찾아 읽을 수 있습니다. 모바일은 설정과 질문 목록을 각각 메뉴로 열며, 답변 수준·응답 시간 옆에서 실제 출처를 확인합니다. 기존 요약 옵션과 모델 선택은 그대로입니다.

시퀀스 분석의 `text_guide`는 “도막 분포 확인 후 보완 권장”, “2구역으로 이동 권장”, “분사 중지”처럼 60자 이내의 짧은 명사형으로 안내합니다. “과도막 면적”은 공식 구역 전체 중 세션의 정상범위 상한을 초과한 면적 비율입니다. 기본 정상범위는 160~200µm이며, 200µm는 정상범위에 포함됩니다. 상세 수치와 근거는 도막 진행·피드백 필드에서 확인할 수 있습니다. 새 문구는 새 분석에 적용되며 이미 저장된 응답 캐시는 유지합니다.

세션 시작 응답의 `first_zone_id`와 `first_zone_guidance`에서 첫 작업 Zone을 확인할 수 있습니다. 스프레이·블라스팅별로 등록된 기준 순서를 사용하며, 기준이 없는 실전·Unit 콘텐츠는 안내 불가 사유를 반환합니다.

DB뷰어 학습데이터의 작업자·공정·시나리오·품질 필터는 서로 연동됩니다. 다른 선택 조건과 검색어에서 데이터가 있는 값만 선택할 수 있습니다. 공동 서버의 시험·교체는 [운영 점유 절차](deploy/spark/README.md)에 따라 시작·종료를 등록해 Slack으로 공유합니다.

## 주요 기능

| 기능 | 설명 |
|---|---|
| Home·학습자료 | 등록 자료 현황·변경 이력과 검색 색인의 문서별 텍스트를 확인합니다. v3.12 소스에 추가한 화면입니다. |
| 훈련 세션 관리 | 훈련 시작부터 시퀀스 수집, 종료, 결과 조회까지 세션 단위로 관리합니다. |
| 시퀀스 피드백 | 입력된 시퀀스를 분석해 작업 상태와 속도·이격거리 가이드를 제공합니다. |
| 전문가 기준 비교 | 작업 자세, Zone별 도장 방식과 작업 순서를 전문가 데이터와 비교합니다. |
| 텍스트·음성 질의 | 훈련 맥락과 관련 지식을 활용해 답변합니다. 빠른 안내와 상세 분석을 선택할 수 있습니다. |
| 훈련 리포트 | 업로드된 기록과 높이맵을 바탕으로 훈련 결과를 정리합니다. |
| 3D 모션뷰어 | 작업자와 전문가의 기록을 재생하며 도장 경로, Zone, 작업 자세와 도막 분포를 확인합니다. |
| DB뷰어 | 세션 상태와 API 호출 이력을 조회합니다. 관리자 모드에서는 관리 정보 수정과 기록 삭제가 가능합니다. |

분석에 필요한 데이터나 기준 자료가 없는 경우에는 API 응답에 분석 가능 여부와 사유를 표시합니다.

## 접속 안내

현재 운영 서버에서는 다음 페이지를 사용할 수 있습니다.

| 페이지 | 용도 |
|---|---|
| [API 문서](http://keti-xr-lab.iptime.org:58000/docs) | API별 입력값과 응답 형식을 확인하고 예제로 호출해 볼 수 있습니다. |
| [DB뷰어](http://keti-xr-lab.iptime.org:58000/admin) | 훈련자, 세션, 시퀀스, 질문·답변, 리포트와 호출 이력을 조회합니다. |
| [3D 모션뷰어](http://keti-xr-lab.iptime.org:58000/motion-viewer) | 훈련 기록을 재생하고 전문가 기준과 비교합니다. |
| [3D 모션뷰어 v2](http://keti-xr-lab.iptime.org:58000/motion-viewer/v2) | 같은 기록을 큰 3D 장면과 오른쪽 고정 질문 열로 재생합니다. 기존 화면은 그대로 둡니다. |

`/home`에서 각 화면으로 이동하며, `/query-chat`의 질문 목록에서 8분야 48개 예시를 고를 수 있습니다. 예시는 자동 전송되지 않고 훈련 기록이 필요한 질문은 따로 표시됩니다. **학습자료**는 현재 검색용 텍스트만 제공하며 원본 PDF·이미지는 아직 등록되어 있지 않습니다. 원본 대조 후 교정한 본문은 교정본으로 표시하고, 오류로 제외한 문단은 본문을 숨깁니다. 추후 별도로 등록한 원본 자료만 연결할 수 있으며 검색 텍스트를 원문 페이지나 그림으로 재현하지 않습니다.

### 모의 연동

- 시뮬레이터 없이 연동 흐름을 확인하려면 API 문서의 **0. 모의 연동**에서 **0-0부터 0-4까지** 순서대로 실행합니다.
- 테스트에 필요한 기본값이 준비되어 있고 응답에서 실제로 사용된 입력값을 확인할 수 있습니다.
- 모의 API는 **모의훈련자**(`COPILOT-DEMO-USER`) 계정을 재사용하고 새 훈련을 시작할 때 세션을 생성합니다.

### 대화 구분

- 질의는 도장 지식뿐 아니라 일반 대화와 후속 질문도 처리합니다. 도장 지식이 필요한 질문에만 `use_rag=Y`의 검색을 적용합니다.
- 모션뷰어는 채팅 창별 대화 식별자를 자동으로 보냅니다. API 클라이언트는 선택 헤더 `X-Copilot-Conversation`으로 대화를 구분할 수 있습니다(영문·숫자·`._:-`, 최대 128자).
- 헤더를 생략하면 같은 사용자·훈련 세션의 기본 대화를 이어갑니다. 훈련 세션이 없는 질의도 사용자별 대화 기록으로 저장합니다.
- 이 식별자는 인증 기능이 아닙니다.

### 호출 출처 표시

- DB뷰어는 훈련 대상 작업자와 호출 채널을 따로 표시합니다. 모션뷰어 호출은 **3D VIEWER**, 자동 검증은 **TEST**, 모의 API는 **TEST API**로 표시하고 API 호출에서 수집한 IP를 보여 줍니다.
- 선택 헤더 `X-Copilot-Source`는 `motion-viewer` 또는 `assistant-test`를 받는 출처 표시용 힌트입니다.
- 과거에 IP를 수집하지 않은 기록은 **미기록**, 파일로 수집한 기록은 **해당 없음**으로 표시합니다.
- 프록시·공유기를 거친 경우 서버에 전달된 주소가 기록되며 실제 작업자 신원을 보증하지 않습니다.

### DB뷰어 권한

- 일반 조회에는 로그인이 필요하지 않습니다. 수정·삭제 기능은 좌측 메뉴 하단의 **관리자 모드**에서 로그인한 뒤 사용할 수 있습니다.
- 삭제 전에는 연결된 기록의 범위를 확인하며 DB 백업과 변경 이력이 저장됩니다.

## 시뮬레이터 연동

기본적으로 아래 순서로 호출합니다.

```text
훈련 시작 → 시퀀스 전송(반복) → 훈련 종료 → 결과 파일 업로드 → 리포트 조회
```

| 메서드 | API | 용도 |
|---|---|---|
| `POST` | `/api/v1/sessions/start` | 훈련 세션을 시작합니다. |
| `POST` | `/api/v1/telemetry/sequence` | 시퀀스 데이터를 저장합니다. |
| `POST` | `/api/v1/copilot/analyze-sequence` | 시퀀스 데이터를 저장하고 피드백을 요청합니다. |
| `POST` | `/api/v1/copilot/query` | 텍스트로 질문합니다. |
| `POST` | `/api/v1/copilot/query-voice` | 녹음한 음성으로 질문합니다. |
| `POST` | `/api/v1/sessions/end` | 훈련을 종료합니다. |
| `POST` | `/api/v1/sessions/complete` | CSV·높이맵 등 결과 파일을 업로드하고 리포트 분석을 요청합니다. |
| `GET` | `/api/v1/reports/{report_id}` | 리포트의 처리 상태와 분석 결과를 조회합니다. |

`telemetry/sequence`와 `analyze-sequence`는 필요한 기능에 따라 선택합니다. 같은 시퀀스를 두 경로에 모두 전송할 필요는 없습니다.
질문 API는 훈련 중에도 사용할 수 있으며 세션 ID를 함께 보내면 저장된 훈련 기록을 답변에 활용할 수 있습니다.
자세한 파라미터와 예시 요청은 [API 문서](http://keti-xr-lab.iptime.org:58000/docs)를 참고하세요.

## 동작 기준

### 도막 두께와 등급

- 두께는 PR #8 도막 기준의 보정값으로 잽니다. 받은 두께에서 10µm를 한 번 빼고 1600µm에서 자릅니다. 1µm 미만은 칠하지 않은 곳으로 봅니다.
- 새로 시작하는 세션에서 목표를 생략하면 기본 목표 160µm로 판정하고 "기본 목표 160µm 기준"으로 표시합니다. 목표를 명시한 세션은 "세션 목표 Nµm 기준"으로 표시합니다.
- Zone 등급은 칠한 곳의 평균 두께로 정합니다. 목표 미만은 저도막, 목표의 1.5배 이상은 과도막입니다.
- 등급은 시퀀스 분석의 `coating_feedback`과 완료 리포트에 실립니다.
- 조절 후보(속도·이격거리)는 규칙에 따른 후보이며 원인으로 확정된 것이 아닙니다.

### 다음 Zone 안내

- 스프레이는 `coating_progress.completion_percent` 원값이 85%에 도달하면 현재 Zone을 완료하고 다음 Zone을 안내합니다. 공식 Zone의 픽셀마다 세션 목표 두께(기본 160µm) 대비 도달률을 최대 100%까지 계산해 평균을 냅니다. 미도장 픽셀은 0%입니다.
- `coverage_percent`는 목표 두께에 도달한 면적 비율입니다. 평균 도막 등급은 기존 정상 범위(기본 160~200µm)를 기준으로 평가하며, 과도막이 발생하면 추가 분사를 멈추라고 안내합니다.
- 부분 크롭은 최신 누적 두께로 덮어쓰고 아직 관측하지 못한 공식 Zone 픽셀도 진행률 계산에 포함합니다.
- 도막 자료나 공식 구역 정보가 없으면 완료로 판단하지 않습니다. 블라스팅에는 이 도막 기준을 적용하지 않습니다.

### 이상 알림

- 이상 알림 SSE로 과도막(`coating_over_app`)과 저도막(`coating_under_app`, 방금 떠난 Zone) 알림을 보냅니다.
- 서버가 떠 있는 동안 세션마다 Zone당 종류별로 한 번씩 보냅니다.

### 모션뷰어 도막 카드와 완료 리포트

- 모션뷰어의 도막 카드는 기록 옆 최종 높이맵으로 잰 목표 대비 평가를 기본으로 보여 줍니다. 한 번 누르면 전문가 최종 도막과 비교한 값으로 바뀝니다.
- 높이맵이 없는 기록은 이유를 밝히고 전문가 대비로 열립니다.
- 완료 리포트의 주 판정은 목표 대비 등급입니다. 전문가 최종 도막과 견준 판정은 보정 전 두께 기준의 참고 정보(`expert_comparison`)로만 함께 실립니다.

### 모션뷰어 불러오기와 캐시

- v3.12 소스는 세션 목록에서 이 창에 보관한 재생 자료를 구분합니다. 캐시는 창을 닫으면 사라지며 크기·건수·보관 시간이 제한됩니다. 선택할 때 원본과 공식 구역 자료의 변경 여부를 서버에서 다시 확인하고, 바뀌었거나 확인할 수 없으면 새로 불러옵니다.
- 로딩 표시는 실제 처리 중인 CSV 행·기록·Zone의 단계와 완료 수를 사용합니다. 총량을 아직 모르면 그대로 표시하며, 전체 작업의 백분율이나 예상 남은 시간을 만들어내지 않습니다. 취소·실패·캐시 복원을 구분하고 기존 프레임·궤적·판정 값을 유지합니다.

### Query 답변 모드

- 빠른 안내는 Qwen3-8B, 상세 분석은 Qwen3.6-27B를 사용합니다.
- `response_mode`는 모델을, `summarize`는 답변 분량을 선택합니다. 텍스트·음성 Query 모두 같은 요약 옵션을 받습니다.
  - `summarize=true`(생략 시 기본값): VR에서 보기 쉽도록 핵심 답변을 요약합니다. 필요한 안전 경고·판정 한계·수치·단위·Zone 순서는 유지하므로 고정된 글자 수 상한은 아닙니다.
  - `summarize=false`: 문단·목록을 유지한 전체 본문을 제공합니다. AI질문 페이지와 모션뷰어 채팅은 이 값을 명시해 기존 상세 표시를 유지합니다.
- 명시적인 번역 요청은 번역할 문구·문장 전체를 보존합니다. 요약을 위해 별도 LLM 호출을 추가하지 않으며 생성 상한은 1,024토큰입니다. 인용·안전·수치·번역 보호는 유지합니다.
- 실제 응답 시간은 질문·검색·번역·서버 부하에 따라 달라집니다.

### 도포 방향 질문

- 모션뷰어에서 "도포 방향은?"이라고 물으면 현재 재생 시점 주변의 Ray Point 궤적으로 방향을 판단해 **수평·수직·대각선·비정형**으로 답합니다.
- 같은 분사 구간 안의 인접 궤적을 사용합니다. 유효한 분사 궤적이 없거나 정지한 시점에는 판단할 수 없다고 안내합니다.
- 전체 기록이나 Zone의 대표 방향을 명시적으로 물으면 해당 범위를 유지합니다.
- 프레임 방향 자료는 서버가 계산·보관하므로, 오래된 화면에서는 재생 기록을 다시 불러와야 합니다.
- TSB의 API 요청 JSON에 새 필수 항목을 추가하지 않습니다.

### Query 지식 근거와 번역

- 질문에 맞는 NCS 문서 근거가 있으면 해당 근거를 바탕으로 LLM이 답변을 작성합니다. 문서 근거를 사용하지 않은 답변은 일반 LLM과 대화·훈련 문맥에 따라 작성하며, NCS로 확인된 내용과 구분합니다.
- 일반 지식 설명은 훈련 기록의 평가 서식과 분리해 질문의 대상·작업 문맥에 맞게 작성합니다. 문서만 근거로 답하도록 요청한 경우에는 확인되지 않은 내용을 일반 지식으로 보충하지 않습니다. 문서 답변의 인용은 검토에서 실제 지원 근거로 확인한 문단만 남깁니다.
- `retrieval_used=true`와 `citations`는 실제 답변에 사용한 문서 근거를 뜻합니다. 검색을 시도한 사실만으로 RAG 출처나 NCS 인용을 표시하지 않습니다. 문서 근거를 쓰지 않은 일반 LLM·문맥 답변은 `retrieval_used=false`, `citations=[]`입니다. v3.12 AI 질문은 답변 하단의 작은 출처 표시에서 검증된 근거 문단을 열 수 있습니다.
- “노즐을 영어로 번역해줘” 같은 명확한 용어 번역은 검증 용어집을 우선하고, 그다음 활성화된 TSB 참고 용어의 정확한 대역어를 조회합니다. 문장·미등록 용어는 기존 번역 경로로 처리합니다. 용어집 출처는 RAG와 구분하며 NCS 인용을 붙이지 않습니다.
- “영어로 분사 압력 조절 방법을 알려줘”는 원래 지식 질문을 유지하고 답변 언어만 바꿉니다. “그럼 영어로?” 같은 번역 후속 질문은 같은 사용자·세션·대화의 이전 사용자 원문을 사용하며, 모델이 생성한 번역을 사전 근거로 삼지 않습니다.

### 훈련 전 기준 순서 안내

- 훈련 시작 전에도 `scenario_id`로 학습 모드를 알 수 있고 등록된 기준이 있으면 Query API가 Zone 작업 순서를 안내합니다.
- 학습모드 범위는 **1~10**입니다. 실전·Unit의 기준 제공 여부는 등록된 자료로 판단합니다.
- 공정이 없고 스프레이·블라스팅 기준이 모두 있으면 공정별로 구분합니다.
- 기준 안내는 실제 방문 순서·준수율·도막 완료 판정과 별개입니다. 지금 다음 Zone으로 이동할 수 있는지 묻는 질문은 저장된 시퀀스로 판단하며, 시퀀스 피드백과 같은 도막 완료 기준을 씁니다.

### 의견 보내기

- 상단의 **의견 보내기**에서 API 문서·DB뷰어·모션뷰어에 대한 개선 의견을 남길 수 있습니다.
- DB뷰어의 **사용자 의견**에서 조회합니다. 처리 상태 변경은 기존 관리자 인증으로 제한합니다.
- 의견 제출은 훈련자나 훈련 세션을 생성하지 않습니다.
- 질의 채팅의 **개선 필요**는 질문·답변·교정 제안을 DB에 저장하고 관리자 검토를 기다립니다. 관리자 승인과 모델 학습·평가·배포는 별도 단계입니다.
- 업데이트 전 검토 묶음은 아래 CLI로 출력할 수 있습니다. 기존 DB를 읽기 전용으로 열어 출처·ID·상태·사용자 제안과 관리자 교정을 보존하며, 처리 상태를 바꾸거나 자동 학습하지 않습니다. `--include-closed`를 붙이면 제외·처리 완료 항목도 포함합니다.

```bash
docker exec -w /workspace ship-paint-trainer python3 -m trainer.scripts.query_feedback_review \
  --db /output/eval_results/sequences.db
```

### API 출력과 다국어 용어

- Swagger의 각 API에서 **출력 파라미터**와 **응답 예시**를 확인할 수 있습니다. 중첩 필드·타입·허용값과 `null`·분석 대기·판정 불가의 의미를 설명합니다. 예시 값은 실제 분석 결과와 구분합니다.
- 음성 Query는 8~192kHz의 mono PCM16 WAV를 받아 서버에서 16kHz로 변환합니다. 최대 15초·6MiB이며, 44.1kHz·48kHz 입력에도 별도 파라미터가 필요 없습니다.
- TSB가 제공한 세 언어 CSV의 1,004행을 출처·원문·품질 표시와 함께 보존했습니다. 우선 13개 용어, 68개 언어쌍을 텍스트·음성 질의 번역의 선택 참고자료로 사용합니다.
- 원문 보존과 활성 용어 승인은 별개입니다. 미검토 행이나 긴 문장에서 일부를 잘라 새 사전 정답으로 올리지 않으며, TSB 참고 대역어를 공식 기술 근거로 표시하지 않습니다.
- 언어 열이나 노즐 번호가 어긋난 항목, 동적 ID가 바뀐 문구, 번역 충돌은 보류합니다. 기존 검증 용어집과 숫자·단위·ID 보호가 우선합니다. 싱할라어 참고 항목은 보류하고, 현재 API에 없는 벵골어는 자료로만 보관합니다.
- 이 자료는 번역 참고에 사용합니다. LLM 가중치 학습과 전문 기술 판정의 근거는 별도로 관리합니다.

## 데이터 구성

전문가 비교에 사용하는 자료와 API 운영 기록은 별도로 관리합니다.

DB뷰어의 **학습 데이터 → 구축 검증**에서는 훈련 CSV가 기록별 학습 JSON으로 구성되는 과정과 검증 결과를 확인합니다. 기록을 선택하면 전체·Zone별 통계, 원천 일부 행, 저장된 도막 분석, JSON과 해당 기록의 3D 재생을 함께 볼 수 있습니다. 학습 JSON에는 추출된 특징·통계가 저장되며 전체 모션은 연결된 원천 CSV로 재생합니다.

관리자는 한 건의 CSV 특징을 실제로 재추출해 시험 표본 JSON을 내려받을 수 있습니다. 등록 자료는 바뀌지 않고, 실행 결과는 제한된 시간 동안 메모리에만 남습니다. 품질 완료 건수는 기술적 구축 수량이며 작업자의 숙련 자격이나 LLM 가중치 학습 완료를 뜻하지 않습니다.

- **전문가 기준 자료**: Zone ID가 포함된 CSV, 도막 높이맵 PNG와 이를 가공한 비교 프로필입니다. 훈련자의 작업을 평가하는 기준으로 사용합니다.
- **API 운영 기록**: 세션, 시퀀스, 질문·답변, 리포트와 API 호출 이력입니다. SQLite에 저장되며 DB뷰어에서 확인할 수 있습니다.
- DB뷰어의 **시퀀스 분석 결과** 목록에는 `result.text_guide` 안내문을 별도 열로 표시합니다. 원본 JSON과 상세 보기도 그대로 확인할 수 있습니다.
- **모델·검색 자료**: LLM 모델, 학습 어댑터와 RAG 검색 인덱스입니다. 지식 검색과 답변 생성에 사용합니다.
- 신규 훈련 코퍼스는 원본 출처와 Zone ID 유무를 보존하는 기록별 학습용 JSON으로 등록합니다. LLM 추가 학습이나 전문가 판단 기준 교체는 별도 작업입니다.
- v3.12의 작업자 통계·필터는 이름 미확인을 한 그룹으로 보여 주되 모든 원본 ID를 보존합니다. 같은 파일명은 중복 근거가 아닙니다. 선언 hash가 같은 45개 후보는 빈 기록·1프레임 기록과 인물·날짜 충돌을 포함해 삭제하지 않았습니다.
- Zone 정보가 없는 기록의 자동 구역 복원은 이번 변경에 포함하지 않습니다. 실제 착탄 좌표, 공식 구역 라벨맵과 텍스처·좌표 변환의 정합을 검증해야 하므로 자료가 없으면 가능 여부를 확정할 수 없습니다. 누락값을 추정해 품질 완료로 올리지 않습니다.

원본 훈련 데이터, 모델 파일, 운영 DB와 인증 정보는 이 저장소에 포함하지 않습니다. 새 환경에 배포할 때는 아래 "모델·데이터 배치"대로 따로 준비합니다.

## 개발과 배포

운영 서버는 DGX Spark에서 Docker Compose로 실행합니다. 환경 준비와 자산 배치, 이미지 빌드·기동 방법은 [Spark 배포 안내](deploy/spark/README.md)를 참고하세요.
DB뷰어와 3D 모션뷰어는 FastAPI 서버에서 제공하며 `demo-ui/`의 개발 콘솔과는 별도로 사용할 수 있습니다.

Python 명령은 프로젝트 의존성이 설치된 컨테이너의 저장소 루트(`/workspace`)에서 실행합니다.

```bash
# API 검사
python3 -m pytest trainer/demo_api/tests -q

# 전체 Python 검사
python3 -m pytest trainer mcp_servers -q
```

일부 통합 검사는 모델과 기준 데이터가 준비된 환경에서 실행해야 합니다.
웹·Electron 콘솔을 수정할 때는 `demo-ui/`에서 빌드와 검사를 실행합니다.

```bash
cd demo-ui
npm ci
npm run build:web
npm test
```

## 릴리스 관리

기능 추가는 `MINOR`, 호환되는 오류 수정은 `PATCH`, 호환되지 않는 변경은 `MAJOR`를 올립니다. API 경로의 `/api/v1`과 소스 릴리스 버전은 별도로 관리합니다.

### 브랜치

- `main`은 개발 통합 브랜치입니다.
- `release` 브랜치와 버전 태그에는 API 서버(agent-api, MCP) 운영에 필요한 코드·설정·배포 정의와 배포 PC용 README만 담습니다(`deploy/release/release_files.txt`). 문서, 테스트, 학습·평가 스크립트, 웹 UI(demo-ui)는 넣지 않습니다.
- `release`는 main 이력과 끊긴 별도 이력입니다. 배포 PC는 `git clone --single-branch --branch release <저장소 주소>`로 받고 이후 `git pull --ff-only`로 갱신합니다.
- 개발 문서(설계·측정·보고 자료)는 어느 브랜치에도 올리지 않습니다([저장소 추적 범위](docs/repository-hygiene.md)).

### 릴리스 만드는 순서

1. 운영 점유와 다른 작업자의 버전 예약을 확인하고 사용할 버전을 예약합니다. `main`에서 `trainer/demo_api/__init__.py`와 `CHANGELOG.md`를 같은 버전으로 맞추고 관련 검사를 마칩니다. 운영 반영 전에는 운영 검증 완료로 기록하지 않습니다.
2. 새 운영 모듈·데이터가 빠지지 않도록 `deploy/release/release_files.txt`를 검토합니다. 게시할 `main` 커밋의 정확한 40자리 SHA를 고정하고, 해당 소스와 allowlist·배포 PC용 README로 구성한 **배포 트리 전체**를 컨테이너에서 import 검사합니다. 검사한 트리 SHA를 기록합니다.
3. 저장소의 **Actions → Publish release → Run workflow**에서 `main`의 수동 워크플로를 실행합니다. `source_sha`에는 검증한 원본 커밋, `tag`에는 예약한 `vX.Y.Z`, `expected_release_tree`에는 실제 컨테이너에서 import 검사한 트리 SHA를 입력합니다. `make_latest`는 이 버전을 최신 안정 릴리스로 지정할 때 선택합니다.
4. 워크플로가 원본 버전과 배포 트리의 정확한 일치를 확인한 뒤 별도 `release` 이력과 **주석 태그(annotated tag)**를 게시합니다. 게시 결과는 Actions 요약과 **Releases**에서 확인합니다. `main`에 태그를 붙이거나 워크플로 파일을 수정하는 것만으로 자동 게시하지 않습니다.

기존 태그를 재사용할 때도 주석 태그의 원본 `source_sha`와 검사한 배포 트리가 일치하는지 검증합니다. 태그를 이동하거나 덮어쓰지 않습니다. 소스 릴리스 게시와 운영 서버 배포는 별도 절차이며, 태그를 게시해도 운영 서버가 자동으로 재시작되지는 않습니다.

## 보정 도막 평가·Zone 코칭 통합

선택적 v2 경로의 설치 준비, 변경 위치, API 연결, 시험 범위는 [통합 안내](docs/corrected-zone/README_KR.md)를 참고하세요.

- 선택적 v2 서비스(엔진·설명·`/api/v2`)는 기본으로 꺼져 있고 따로 켜야 합니다.
- v1 요청의 도막 판정은 같은 계산 함수(`trainer/zone_engine/numerical.py`)를 서버 안에서 직접 불러 씁니다(`trainer/demo_api/coating_assessment.py`).
