RAG 검색 결과, 평가셋 정답, 도메인 자료, 기존 교육 자료 등 SFT 데이터 생성을 위한 모든 소스 데이터를 수집하고 정리

**Details:**

Task 2(문서 수집)와 Task 6(평가 데이터셋)으로부터 원본 데이터를 수집합니다. /data/raw/ 문서들을 정규화하고, RAG 검색 결과를 추출하여 /data/sources/ 디렉터리에 저장합니다. 각 소스별로 메타데이터(doc_id, category, confidence)를 포함한 manifest를 작성하고, 소스 균형을 검증하여 6개 카테고리별 충분한 데이터 가용성을 확인합니다.

### 7.2. generate_sft.py 스크립트 개발 및 데이터셋 자동 생성

**Status:** done  
**Dependencies:** 7.1  

템플릿 기반 자동 생성 스크립트를 개발하여 6개 카테고리(문서QA 100, 절차설명 80, 결함분석 60, DFT 60, 용어/다국어 50, 요약/비교 50)별 300-500건 SFT 데이터셋 생성

**Details:**

/workspace/trainer/scripts/generate_sft.py 개발: (1) 각 카테고리별 프롬프트 템플릿 정의, (2) 소스 데이터에서 user-assistant 쌍 추출 로직, (3) system message 통일 적용('너는 선박 도장 훈련 코치다...'), (4) 근거 문서 ID 자동 추가, (5) JSON Lines 포맷({messages, category})으로 저장. 카테고리별 목표 수량 달성하도록 템플릿 가중치 조정. /data/sft/ 디렉터리에 임시 파일들 생성.

### 7.3. 중복 제거 및 데이터 정제

**Status:** done  
**Dependencies:** None  

100자 이상 문장 유사도 기반으로 중복 데이터를 제거하고, 포맷 오류 및 불완전한 데이터를 정제

**Details:**

중복 제거 로직 구현: (1) 생성된 전체 데이터 로드, (2) 각 assistant 응답에 대해 100자 이상인 경우만 유사도 계산(cosine similarity, 임베딩은 sentence-transformers 활용), (3) 유사도 > 0.95인 경우 중복으로 표시하고 먼저 생성된 데이터 보존, 뒤의 데이터 제거, (4) 포맷 검증(required fields 확인), (5) 비정상 데이터(빈 응답, 너무 짧은 응답 <10자) 제거. 처리 결과를 로그에 기록(제거 건수, 정제 건수).

### 7.4. 카테고리 균형 검증 및 학습/검증 데이터 분할

**Status:** done  
**Dependencies:** 7.3  

카테고리별 데이터 수량이 균형을 이루는지 검증하고, 학습용/검증용으로 데이터 분할

**Details:**

데이터 분할 및 검증 로직: (1) 정제된 데이터에서 각 카테고리별 수량 계산, (2) 목표 대비 편차 확인(±10% 범위): 문서QA 100±10, 절차설명 80±8, 결함분석 60±6, DFT 60±6, 용어 50±5, 요약/비교 50±5, (3) 편차 초과 시 카테고리 재조정(부족 카테고리는 템플릿 가중치 조정, 과다 카테고리는 일부 제거), (4) 재조정 후 균형 재검증. (5) 균형 달성 후 random seed 고정하여 학습용 380-450건(80-90%), 검증용 20-50건(10-20%) 분할. 각각 /data/sft/sft_train.jsonl, /data/sft/sft_val.jsonl로 저장.

**Status:** done  
**Dependencies:** 7.4  

최소 30% 샘플에 대해 5차원 루브릭 기반 품질 검사를 수행하고, 평균 점수 ≥1.5/2.0 달성 여부 검증

**Details:**

/workspace/trainer/scripts/review_sft.py 개발 및 실행: (1) 학습용 데이터에서 최소 100건(전체의 30% 이상) 무작위 샘플링, (2) 5차원 루브릭 적용: 기술정확성(도장/분석 정확성), 충실도(근거 충분성), 용어(도메인 용어 정확성), 완전성(답변 완전성), 한국어(문법/자연스러움). 각 차원별 0/1/2점 평가, (3) 샘플별 평균 점수 계산, (4) 전체 샘플 평균 점수 계산(≥1.5/2.0 필수), (5) 점수 분포 분석(차원별, 카테고리별), (6) 검수 결과 리포트 생성(/data/sft/quality_report.json). 평균 점수 <1.5인 경우 데이터 재생성/수정 필요. 최종 검증: 학습/검증 파일 JSON Lines 포맷 유효성 100%, 행 수 범위 확인, 샘플 점수 기록.
