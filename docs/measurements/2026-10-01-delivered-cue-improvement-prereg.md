# 사전등록 — 전달되는 안내 한 건만 따랐을 때의 개선율, 전수

작성 2026-10-01 · 측정 전에 커밋한다 · 실행 스크립트 `trainer/scripts/delivered_cue_study.py`

## 1. 질문

화면의 "안내를 적용했을 때의 예상 결과"는 993e30e부터 **작업자에게 실제로 전달되는 안내 한 건**
(σ 1위, `measured_score.DELIVERED_CUES` = 1)만 따랐다고 보고 계산한다. 사용자 요구(2026-10-01):

> 오른손을 10.2cm 올리라는 안내가 나와서 올렸을 때 자세가 어떻게 변하며 자세 유사도는 그에 따라서
> 어떻게 개선될 것인지를 모든 데이터에 대해서 다 분석해서 평균 개선율을 구하는 거야.

지금까지 인용한 91.58%(C1, be78b30)는 **발부된 축 전부**를 적용한 값이고 200쌍 표본이다.
이번에는 (a) 한 건만, (b) 색인된 패스 전부로 다시 잰다.

## 2. 고정하는 것

| 항목 | 값 |
|---|---|
| 코퍼스 | `/data/sources/professionals`, 색인 캐시 `/output/samelevel/index_cache_m3.json`(64,098 패스, 479 세션, 지문 일치 확인) |
| 산포 아티팩트 | `/output/spread_reference_expert_m3.json`(C1과 같다) |

| 교정 적용 | `service.compare(include_view=False)`가 내는 값을 그대로 읽는다. 1건 = `improvement`·`score_after`, 전부 = `improvement_all`·`score_after_all` |

| 문턱 | 0.70(goal_year2) |

## 3. 보고할 숫자 (이 순서로)

1. **1건 split 개선율의 평균**(사용자가 물은 "평균 개선율"), 중앙값, 사분위, ≥0.70 비율, 0 미만(악화) 비율.
2. 1건 유사도 상승폭 평균·중앙값.
3. 같은 쌍에서 발부 전부(`all_issued`)의 같은 숫자 — 1건과 나란히.
4. 1건으로 전달된 안내의 종류 분포(점/축).
5. 작업자별 1건 split 평균 — 한 사람이 평균을 끌고 가는지.
6. 전형기 자신의 패스를 뺀 값.

평균은 0 미만 꼬리에 민감하다(S0가 1에 가까우면 분모가 작다). 평균과 중앙값을 **둘 다** 싣고,
둘이 0.10 이상 벌어지면 그 이유(꼬리)를 결과 문서에 적는다.

## 4. 예측 (측정 전)

시간 재기로 20쌍을 돌렸고 그중 앞 두 줄을 보았다(split 1건 0.0000·0.113, 전부 0.42·0.77).
이 두 값을 본 뒤에 적는 예측임을 밝힌다.

- 1건 split 평균 **0.30**(그럴듯한 범위 0.15–0.45), 중앙값 0.30 근처.
- 1건 ≥0.70 비율 **10%**(5–20%).
- 1건 상승폭 평균 **+0.10**.
- 발부 전부의 split ≥0.70 비율은 C1(91.58%, 200쌍)에서 **±5%p 안**. 벗어나면 200쌍 표본이
  전수를 대표하지 못했다고 쓴다.

## 5. 판정

- 사용자에게 내는 "평균 개선율"은 §3-1의 평균이다. 70% 목표에 대한 판정은 ≥0.70 비율로 한다
  (기존 지표 정의 유지). 1건 기준으로 70%에 못 미치면 **못 미친다고 쓴다** — 문턱·모집단을 옮기지 않는다.
- 범위: 숙련자 대 숙련자다. 코퍼스에 훈련생이 없다. 계산상 예상값이지 재측정이 아니다.
