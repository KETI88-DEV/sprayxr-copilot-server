# 로컬 다국어 rc.1 검증 기록

확인일: 2026-10-06. 대상: `keti@spark-8bb9`, GB10/aarch64. 이 문서는 실제 호출과 미완료 평가를 구분한다. 최종 활성 언어는 **한국어·영어·중국어**이고 베트남어·우즈벡어·미얀마어·네팔어는 비활성이다.

## 1. 모델 결정의 실측 근거

현재 Spark는 `qwen36-27b-shipcoat-v6-1-bf16`를 제공하며 `/home/keti/shipcoat/models/whisper-large-v3-turbo` 가중치가 있다. 기존 agent-api에도 저장소와 다른 음성 API 코드가 존재하므로 새 평가 서비스는 별도 이미지·컨테이너·포트로 배포했다.

최초 Qwen 번역 실험에서 영어 문장은 3.052초에 생성됐으나, 긴 한국어 도장 답변을 베트남어로 번역하라는 요청에는 한국어 `[문서]`와 `[질문]` 형식으로 답했다. 번역 예시 한 쌍을 추가하면 해당 문장은 번역됐지만, 다른 실제 RAG 답변에서는 다시 실패했다. 따라서 “번역 가능한 사례가 있다”를 언어 출시 근거로 삼지 않고 베트남어를 비활성화했다.

영어·중국어는 한국어 답변 출력과 외국어 질문 입력을 각각 실제 API로 확인했다. 이것은 몇 개의 smoke 결과이며 전체 기술 용어·언어별 현장 품질 승인이나 실패율 추정은 아니다. 아직 Gemma 가중치를 로드하거나 성능을 측정하지 않았다. **Qwen의 지시 준수 실패는 Gemma 공통 모델을 우선 비교해야 하는 실제 근거**다.

## 2. 음성 인식

공개 [Google Gemma 음성 예제](https://ai.google.dev/gemma/docs/audio/roses-are.wav)를 PCM16·mono·16kHz WAV로 변환해 사용했다. 실제로 인식한 문장은 `Roses are red. Violets are blue.`다. 원음은 저장소에 포함하지 않는다.

| 호출 | HTTP | 서버 처리 시간 | 결과 |
|---|---|---|---|
| 첫 추론 | 200 | 1,186 ms | 원문 전사·확인 필요 표시 |
| 동일 파일 warm 재호출 | 200 | 134 ms | 같은 전사 |

첫 구현은 Whisper의 후처리된 토큰 배열에서 EOS를 검사해 정상 완료를 잘림으로 오인했다. 원시 generation 반환 객체를 사용하도록 수정했고 해당 경계에 회귀 테스트를 추가했다. 전사된 질문을 자동으로 Co-Pilot에 보내지 않는다.

한국어·중국어의 현장 화자 녹음, 소음·숫자·단위별 CER/WER는 미측정이다. 위 영어 샘플 시간을 모든 언어·15초 발화의 성능으로 일반화하지 않는다.

## 3. 실제 RAG + 번역

질문은 한국어 “저도막이 뭐야? 짧게 설명해 주세요.”, 입력 번역 시험은 각 언어의 DFT 정의 질문이다. 기존 RAG의 샘플링으로 한국어 답변 길이가 달라져 언어 간 공정한 속도 비교용 측정은 아니다. 시간은 서버 monotonic clock의 실제 구간이다.

| 경로 | HTTP / 현지화 상태 | 입력 번역 | RAG·생성 | 출력 번역 | 전체 |
|---|---|---:|---:|---:|---:|
| 한국어→영어 | 200 / translated | 0 ms | 16,834 ms | 9,712 ms | 26,546 ms |
| 한국어→중국어 | 200 / translated | 0 ms | 15,566 ms | 12,787 ms | 28,354 ms |
| 한국어→베트남어 | 200 / fallback_original | 0 ms | 30,005 ms | 20,110 ms | 50,116 ms |
| 영어 질문→한국어 | 200 / unchanged | 10,020 ms | 18,278 ms | 0 ms | 28,298 ms |
| 중국어 질문→한국어 | 200 / unchanged | 5,605 ms | 12,045 ms | 0 ms | 17,650 ms |
| 베트남어 질문→한국어 | 200 / unchanged | 3,054 ms | 17,519 ms | 0 ms | 20,573 ms |

베트남어 입력 한 건은 처리됐지만 출력이 실패했기 때문에 언어 전체를 1차 활성 목록에서 뺐다. `fallback_original`일 때 한국어 분석·근거는 보존되고 번역문은 null이다. 베트남어 입력/출력의 양방향 지원 완료로 표시하지 않는다.

확인된 영어·중국어 출력 예시는 각각 “Low DFT refers to a condition…”과 “低膜厚（Low film coating）…”으로 시작했다. 답변은 문서 근거와 함께 반환됐다. **추가 번역은 전체 응답시간을 늘렸으며 4초 RAG를 달성한 것이 아니다.**

## 4. 검증 범위

- 신규 단위/API 테스트: 미지원 언어, 비지식 task, 숫자·단위·ID·비교기호 보존, 한국어 번역 생략, 입력 번역 실패 시 분석 미실행, 출력 실패 시 정본 보존, 빈/잘린/잘못된 언어 출력, null 모델 응답, WAV 손상/형식, 전사 확인 단계, EOS 회귀, readiness.
- Python 전체 회귀 테스트: `docker exec -w /workspace ship-paint-trainer python3 -m pytest trainer mcp_servers -q` → **1,830 passed**, 278.19초, 기존 SWIG 관련 경고 2건. 신규 테스트 24개 포함.
- 실제 Spark에서는 ARM64 이미지 빌드, 로컬 모델 로드, readiness, 전사, RAG·번역을 호출했다.
- 미완료: 전체 언어별 원어민/도장 전문가 평가, 한국어·중국어 실제 음성 평가, 30분 혼합 부하, p95 벤치마크, 인터넷 차단 재시작, Gemma 교대 모델 평가, 기존 UI 통합.

## 5. 운영 관찰

기존 서비스 가동 상태에서 약 19 GiB의 가용 메모리를 확인했고 새 Whisper 프로세스 가동 후 약 16 GiB였다. swap은 최초 약 3.4 GiB, 후속 관측에서 약 5.2 GiB였다. 평가 서비스의 restart count는 0, OOMKilled는 false였다. 다른 서비스도 실행 중이므로 증가 원인을 새 서비스 하나로 단정하지 않는다. 이는 시점 관측이고 최악 부하의 안전 여유 검증이 아니다. 기존 모델과 Gemma를 무계획으로 함께 로드하지 않는다.

Spark의 `query-voice`는 ko/vi/id/th를 허용하는 별도 기존 코드였다. 신규 API의 ko/en/zh와 혼동하지 않는다. 이번 배포는 기존 컨테이너·모델·API 계약을 교체하지 않았다.
