# 학습 데이터 구축 검증

DB의 **학습 데이터 → 구축 검증** 탭에서 등록 건수와 검증 통과 건수를 구분합니다. 같은 공정의 훈련 기록 한 번에서 가공한 **JSON 1개와 연결된 원천 CSV를 1건**으로 집계합니다. 복사본과 같은 공정의 동일 원천 바이트는 중복 제외합니다. 공인시험에서 확인하려는 연구목표 1,000건 충족 여부는 현재 파일과 일치하는 회차의 `summary.valid`와 `goal_met`로 확인합니다. 등록 건수, JSON 통과 건수만으로 충족했다고 판단하지 않습니다.

화면의 **검증 시작**은 새 회차의 JSON·원천 SHA-256 점검입니다. **JSON 보기**는 가공 자료 조회이며 **3D 재생** 링크를 여는 것만으로 재생 통과가 기록되지는 않습니다. 실제 브라우저에서 시작·중간·끝 구간의 재생 시간, 원천 프레임 인덱스, 캔버스 그리기 횟수가 모두 증가한 증빙을 별도로 제출해야 합니다. 뷰어는 3D 장면을 `canvas-2d`로 그립니다.

검증 범위는 세 구간 표본입니다. 전체 시간의 연속 재생, Zone 보강본 사이의 원래 모션 동일성, 라벨 정확도, AI 답변 정확도는 포함하지 않습니다. 구축·검증 건수는 모델 가중치 학습이나 배포 완료 건수가 아닙니다.

## 운영자 재현 명령

Node.js와 `demo-ui`에 설치된 `@playwright/test`, 해당 버전의 Playwright Chromium이 필요합니다. 의존성이 없으면 `demo-ui`에서 `npm ci` 후 `npx playwright install chromium`을 실행합니다. 루트는 npm 패키지가 아닙니다. 별도 설치를 쓰려면 `PLAYBACK_PLAYWRIGHT_MODULE`에 Playwright 또는 `@playwright/test` 모듈의 **절대 경로**를 지정합니다. 기본 번들 브라우저 대신 기존 브라우저를 사용하려면 `PLAYBACK_BROWSER_EXECUTABLE`에 실행 파일의 **절대 경로**를 지정합니다. 파일이 없거나 상대 경로이면 실행 전에 중단합니다. 개인 PC 경로는 도구에 내장하지 않습니다.

기존 JSON·원천 점검이 끝났고 현재 파일과 일치하는 회차가 있어야 합니다. 이 도구는 새 회차를 시작하거나 원천 자료를 수정하지 않습니다. 공유 Spark를 대상으로 실행하기 전 `deploy/spark/README.md` §21의 운영 잠금 절차에 따라 테스트를 등록하고 소유권을 확인합니다.

관리자 인증 파일은 Git 작업 트리 밖의 접근 제한된 위치에 JSON 객체로 준비합니다. 필드는 `username`, `password`이며 값은 기존 DB 관리자 계정을 사용합니다. 인증 값을 명령줄이나 환경 변수에 넣지 않습니다. 출력 폴더도 Git 밖을 지정합니다. 아래 경로와 URL은 실제 운영자가 정한 값으로 바꿉니다.

```powershell
node trainer/scripts/verify_training_playback.cjs --help
node trainer/scripts/verify_training_playback.cjs `
  --base-url https://copilot.example.org `
  --credentials-file C:/private/copilot-admin.json `
  --output-dir C:/private/playback-evidence
```

기본값은 JSON·원천을 통과하고 중복이 아닌 **미검증 1건**입니다. `--max-records 5`처럼 1~25건을 지정할 수 있으며 한 번에 한 페이지에서 순서대로 확인합니다. 실패하면 해당 실패 증빙을 제출하고 다음 건으로 넘어가지 않습니다. `--dataset-id <32자리 소문자 16진수>`는 기존 통과·실패 건을 포함한 **명시적 1건 재검사**입니다. 재검사는 같은 회차의 해당 브라우저 결과를 갱신합니다.

페이지 이동은 45초, 모션 준비는 120초, 구간별 재생 진행 대기는 10초로 제한합니다. 타임라인 탐색도 최대 24단계로 제한합니다. 선택 API가 정한 데이터·세션·작업자·공정·학습모드와 실제 렌더링 상태를 대조합니다. 원래 카탈로그의 작업자·세션과 뷰어 선택용 별칭이 다를 수 있으므로 선택 API의 매핑을 사용합니다.

인증과 증빙 제출은 모두 `--base-url`의 같은 백엔드에 관리자 쿠키·Origin·`X-DB-CSRF`로 보냅니다. 인증 파일과 토큰은 결과에 저장하거나 출력하지 않습니다. 관리자의 로그인·로그아웃 및 재생 증빙 기록 외의 쓰기는 하지 않습니다. 쓰기 응답이 불확실하면 자동 재전송하지 않습니다.

## 증빙과 한계

출력 폴더 아래 새 `playback-*` 폴더에 전후 보고서, 건별 증빙, 요약을 저장합니다. 건별 파일은 실제 회차 ID, JSON·원천·카탈로그 해시, 보고서의 앱·뷰어·검증기 버전 정보를 보존합니다. 실패 파일은 확보한 표본만 남기며 통과로 보정하지 않습니다. 제출 확인이 안 된 건은 `submission_unconfirmed`로 남으므로 대시보드와 대조해야 합니다. 실패 시 화면 캡처가 생성될 수 있고 보고서에는 훈련 기록 식별 정보가 있으므로 운영 증빙으로 접근을 제한합니다. 종료 코드는 0(통과 또는 대상 없음), 1(입력 오류·중단·제출 미확인), 2(재생 실패 증빙 접수)입니다.

보고서는 `GET /admin/api/training-verification/export.json`과 `/export.csv`로도 읽기 전용 내보내기를 할 수 있습니다. 새 점검 시작과 증빙 기록은 관리자 인증·CSRF를 요구합니다. 파일·카탈로그 변경은 모든 회차의 현재 유효 건수에서 제외합니다. `viewer_canonical_sha256`을 기록한 새 회차는 정규화한 뷰어 코드 변경도 감지합니다. 해당 필드가 없는 구형 회차의 원시 뷰어 해시는 당시 이력이며, 코드 동등성은 별도로 확인해야 합니다. 새 점검 여부는 운영자가 판단합니다. 새 점검을 시작하면 새 회차의 브라우저 증빙 범위가 생성되며 이전 통과를 자동 승계하지 않습니다. 이전 회차 파일은 보존됩니다.

대형 모션의 서버 캐시 메모리 문제(#47)가 확인되어 있습니다. 페이지를 닫거나 건수를 25건으로 제한하는 것은 서버 캐시를 회수하지 않습니다. **전수 일괄 검증에는 제한된 작업량마다 서버 조회 워커를 교체하는 별도 운영 절차가 필요합니다.** 이 범용 도구는 워커 교체, 서버 재시작, 병렬 처리, 전체 자료 자동 반복을 구현하지 않습니다. 여러 번 연속 실행하여 전수 처리하는 용도로 사용하지 않습니다.

2026-11-19 메인 서버 v3.13.0에서 이 도구로 짧은 스프레이 기록 1건을 명시적으로 재검사했습니다. 실제 선택·로딩, 시작·중간·끝 재생 진행, 관리자 증빙 접수와 로그아웃을 확인했습니다. 전후 유효 건수는 1,201건으로 같았고 JSON·원천 해시는 모두 유지됐습니다. 해당 1건의 마지막 재생 증빙만 갱신됐습니다. 이는 범용 도구의 실제 1건 확인이며 전수 실행 성능을 뜻하지 않습니다.

## 2026-11-19 전수 검증 결과

메인 서버의 품질 완료 자료 1,201건(스프레이 795건·블라스팅 406건, 학습모드 1~10)을 별도 운영 러너로 확인했습니다. JSON·연결 원천 파일의 SHA-256 검사와 실제 시작·중간·끝 구간 재생이 모두 통과했으며 중복 제외·실패·미검증은 각각 0건입니다. 별도 증빙 대조에서도 1,201건 모두 일치했습니다. 연구목표 1,000건을 충족하며 모델 가중치 학습 완료를 의미하지 않습니다.

첫 재생 검사에서는 1,188건 통과와 시간 초과 13건을 기록했습니다. 기존 실패 자료를 보존한 뒤 해당 13건을 각각 한 번, 단일 조회 환경에서 다시 검사해 모두 실제 통과했습니다. 검사 중 큰 기록의 대기 시간과 조회 워커 수명 관리가 조정됐으며 재생 판정 조건은 유지했습니다. 재생 전 구간이나 FPS·모션 정확도를 검증한 결과는 아닙니다. 원래 전수 결과와 이후 범용 도구의 1건 재검사 자료는 구분해 보존합니다.
