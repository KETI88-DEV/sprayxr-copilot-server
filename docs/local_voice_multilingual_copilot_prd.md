## 0. 2026-10-06 1차 배포 결정

사용자 지시에 따라 현지 문서의 실제 표기를 대조하고 [용어 출처·항목별 판정](local_voice_multilingual_terminology.md)을 작성했다. 기존 미검수 번역 후보는 운영 용어에서 제외했다. **한국어·영어·중국어만 우선 활성화한다.** 베트남어는 용어 문서는 확보했지만 Spark 실측에서 Qwen이 한국어를 반환하는 실패가 재현돼 보류했다. 우즈벡어·미얀마어·네팔어도 API에서 명시적으로 거부한다. 미얀마·네팔 자료는 확보했지만 글꼴/문자 추출 문제와 핵심 용어·음성 품질의 검증 공백이 남았다.

실행 구성은 `trainer/multilingual/service.py`, 배포본은 [Spark multilingual rc.1](../deploy/spark/multilingual/README.md)이다. 세 언어가 **하나의 Whisper 가중치와 하나의 기존 Qwen 27B 가중치**를 공유한다. 국가별 모델을 추가하지 않는다. ASR부터 RAG까지 전체를 하나의 가중치로 처리하는 구성은 아직 아니다.

첫 배포는 `knowledge_search` 전용이며, 전사 원문을 확인한 후 별도 질의 API로 전달한다. `/transcriptions`, `/query`, `/languages`, `/ready`와 Swagger를 독립 서비스에서 제공한다. 기존 v2.5 공개 API·기존 UI의 동작을 변경하지 않는다. 현행 Spark에는 저장소와 다른 `query-voice` 코드도 있으므로 해당 컨테이너에 덮어쓰지 않는다.

Qwen은 생성과 입출력 번역을 같은 가중치로 처리한다. 전문 번역 모델을 추가로 상주시켜 메모리를 더 소비하지 않는다. 아래 §5의 TranslateGemma/MADLAD는 비교 후보로 남기되 첫 배포 필수 의존성에서는 제외한다. `glossary.json`에는 네 언어에서 직접 확인한 DFT·표면처리를 기록했고 활성화된 세 언어의 대응만 주입한다. 수치·단위·ID·비교기호가 바뀌면 번역 실패로 처리하고 한국어 정본을 보존한다.

**전체 단일 모델 전환 후보는 Gemma 4 E4B 및 12B Unified다.** 공식 문서에 음성·텍스트 입력과 다국어 전사/번역 기능이 있어 Whisper와 Qwen을 통합하는 방향을 시험할 수 있다. Gemma 4 E4B는 Apache-2.0으로 게시돼 있으며 TranslateGemma의 Gemma 이용조건과 혼동하지 않는다. 다만 전체 언어 수나 평균 벤치마크가 대상 7개 언어의 도장 정확도를 입증하지 않는다. [Gemma 4 카드](https://huggingface.co/google/gemma-4-E4B-it), [공식 음성 처리](https://ai.google.dev/gemma/docs/capabilities/audio)

| 구성 | 국가별 가중치 수 | 장점 | 결정 |
|---|---|---|---|
| Whisper 공통 + 기존 Qwen 공통 | 전체 2개, 언어별 추가 0개 | 기존 도장 튜닝·RAG 재사용, 현재 Spark 모델 활용 | rc.1 |
| Whisper + TranslateGemma + 기존 Qwen | 전체 3개 | 번역 전문 모델 비교 | 1차 제외, 메모리·직렬 지연 증가 |
| Gemma 4 E4B/12B 하나 | 전체 1개 목표 | 음성·번역·답변을 한 모델로 통합 가능 | 언어별 ASR·도장 RAG·MCP/계약 회귀를 통과하면 전환 |

Gemma 4의 공식 대략적 BF16 메모리 표는 E4B 17.9 GB, 12B 26.7 GB이며 문맥 캐시 등 추가 메모리는 따로 필요하다. 확인 당시 Spark 가용 메모리는 약 19 GiB였고 새 Whisper 프로세스 후 약 16 GiB였다. 기존 운영 모델과 새 Gemma를 동시에 올려 비교하는 기본안은 채택하지 않는다. 별도 평가 자원 또는 모델 교대 시험으로 비교한다. [공식 메모리 안내](https://ai.google.dev/gemma/docs/core)

Gemma 교체 시 Qwen용 LoRA를 그대로 붙일 수 없다. 도장 RAG 정답·툴 프로토콜·기존 JSON과 7개 언어의 숫자/부정문/용어를 동일한 평가셋으로 재검증하고 필요하면 Gemma용 학습을 수행한다. 평가는 출처가 확인된 용어집을 정답으로 사용하며, 단일 모델의 일부 언어가 실패하면 합격 언어만 활성화한다. 현재 구현 완료와 사람 검수 완료를 구분하며 이 배포를 정식 7개 언어 제품으로 표시하지 않는다.

통합 모델에서도 전사·검색용 질의 생성·답변 생성이 여러 번의 호출로 남을 수 있다. 가중치 하나로 통합되는 것과 1회 생성 또는 짧은 응답시간을 달성하는 것은 별도 평가 대상이다. Gemma 4 31B/26B의 텍스트 다국어 성능만으로 음성까지 통합할 수 있다고 판단하지 않는다. 음성 지원 모델인 E4B/12B부터 후보로 제한한다.

## 1. 결론과 권장 방향

권장 구조는 **로컬 ASR → 필요 시 한국어 입력 번역 → 기존 Co-Pilot → 답변 본문만 대상 언어 번역 → JSON 반환**이다. 기존 27B 모델과 MCP를 음성 모델로 교체하지 않는다. ASR·번역은 언어 입출력 경계이며 새 MCP 분석 도구가 아니다.

확정된 7개 언어의 공통 ASR 후보는 **Whisper large-v3-turbo/large-v3를 우선 평가**한다. Qwen3-ASR-0.6B는 한국어·영어·중국어·베트남어의 비교 후보이며 우즈벡어·미얀마어·네팔어까지 담당할 수 없다. 번역은 TranslateGemma-4B와 MADLAD-400-3B-MT를 비교한다. **이는 후보 순서이지 최종 모델 선정이 아니다. 언어쌍별 품질, ARM64/GB10 실행, 전문용어 검수, 동시 실행 메모리 게이트를 통과해야 확정한다.**

기존 한국어 질문은 입력 번역을 생략한다. 출력도 한국어이면 출력 번역을 생략한다. 고정 경고·준비 중 안내·오류 안내는 검수된 다국어 템플릿을 사용하고 매번 LLM으로 번역하지 않는다. 분석 수치와 판정은 기존 엔진에서만 만들며 번역기가 재판정하지 않는다.

## 2. 기존 계획과 국가·언어 범위

확인한 계획은 `.taskmaster/docs/ship_painting_optimal_prd_final.md` §11의 **“E-7 대상국 번역 지원 / 다국어 경고·가이드 샘플 생성”**과 후속 ASR/TTS 항목이다. 계획에는 국가 목록이 없어 질의했고, **2026-10-06 사용자 답변으로 한국어·영어·중국어·베트남어·우즈벡어·미얀마어·네팔어를 확정했다.** 또한 “각 나라의 전문용어 대비표를 작성하고 진행”하는 조건을 반영한다. 언어 목록의 근거는 이 사용자 확인이며 일반 E-7 국적 목록으로 확대하지 않는다.

국가와 언어는 일대일이 아니다. 영어 사용자의 국가를 임의로 미국으로 제한하지 않는다. 입력 언어와 출력 언어는 독립 설정이며, 사용자의 국적으로 언어를 자동 결정하지 않는다. 중국어는 보통화 음성·간체 텍스트, 우즈벡어는 라틴 문자를 **초기 제안**으로 두고 사용자 집단과 확인한다.

| 사용자 언어 | API 기본 태그 | 공통 Whisper 전사 후보 | Qwen3-ASR 공식 범위 | 양방향 한국어 번역 | TTS(선택) | 출시 상태 |
|---|---|---|---|---|---|---|
| 한국어 | `ko` | 포함 | 포함 | 생략 | Qwen 후보 | 실측·검수 전 |
| 영어 | `en` | 포함 | 포함 | 평가 필요 | Qwen 후보 | 실측·검수 전 |
| 중국어 | `zh-Hans` | `zh`로 매핑 | `zh`로 매핑 | 평가 필요 | Qwen 후보 | 문자·방언 확인 필요 |
| 베트남어 | `vi` | 포함 | 포함 | 평가 필요 | 별도 후보 필요 | 실측·검수 전 |
| 우즈벡어 | `uz-Latn` | `uz`로 매핑 | 미포함 | 평가 필요 | 별도 후보 필요 | 문자 확인·실측·검수 전 |
| 미얀마어(버마어) | `my` | 포함 | 미포함 | 입력 방향 특히 평가 필요 | 별도 후보 필요 | 실측·검수 전 |
| 네팔어 | `ne` | 포함 | 미포함 | 평가 필요 | 별도 후보 필요 | 실측·검수 전 |

Whisper의 공식 언어 코드에 `ko/en/zh/vi/uz/my/ne`가 포함돼 있다. 코드 지원은 현장 발화 정확도 보장이 아니므로 각 언어를 따로 검증한다. [Whisper 언어 정의](https://github.com/openai/whisper/blob/main/whisper/tokenizer.py)

UI와 API는 BCP 47 언어 태그를 사용하고 모델별 코드로 명시적으로 매핑한다. 출시된 언어만 선택 목록에 표시한다. ASR 지원, 번역 지원, TTS 지원은 각각 독립적으로 표시한다.

## 3. 현행 시스템과 변경 금지 조건

- `trainer/demo_api/copilot_contracts.py`: 질의는 `prompt`, `task_type`, `use_rag: "Y" | "N"` 등을 받는다. `context`는 문자열이고 음성·언어 필드는 현재 없다. 알 수 없는 필드를 기존 요청에 추가하지 않는다.
- `trainer/demo_api/copilot_router.py`: `knowledge_search`는 기존 RAG, `pose_recomm`은 저장된 시퀀스 자세 채점이다. 현재 준비 중인 `trajectory_recomm`/`error_analysis`를 번역 계층에서 구현된 것처럼 만들지 않는다.
- 응답의 `answer`와 `citations`는 분리돼 있다. 본문 번역 때문에 근거 ID·분석 JSON을 다시 생성하지 않는다. `not_available`, `null`, `degraded`의 의미를 유지한다.
- `trainer/configs/rag_config_spark_vllm.yaml`의 `llm.backend: openai`는 **로컬 vLLM의 OpenAI 호환 HTTP 규약**이다. OpenAI 클라우드를 사용한다는 뜻이 아니다. 실제 모델 경로·정밀도는 배포 설정을 기준으로 확인한다.
- `AgentPipeline.run()`의 학습·평가 동작과 HF NF4 경로는 유지한다. 신규 모델 의존성을 개발 컨테이너 전체에 강제하지 않는다.
- 기존 공개 v2.5 API의 요청·응답을 조용히 변경하지 않는다. 아래 신규 경로와 스키마는 **승인이 필요한 확장 제안**이며 현재 제공되는 API가 아니다.

## 4. 사용자 경험 및 처리 흐름

### 4.1 기본 동작

1. 사용자가 입력 언어와 답변 언어를 선택한다. 기본값은 세션에 명시적으로 저장된 설정이며 없으면 한국어다.
2. 마이크 버튼으로 녹음을 시작하고 종료한다(초기 버전은 push-to-talk).
3. 화면에 인식된 원문을 먼저 표시한다. 사용자가 수정하거나 다시 녹음할 수 있다.
4. 초기 버전에서는 확인 버튼을 눌러야 질문이 실행된다. 숫자·단위·구역 ID가 포함된 발화의 무확인 자동 실행은 허용하지 않는다.
5. 외국어 질문은 로컬에서 한국어로 번역한 후 기존 질의 계약으로 전달한다. 작업 종류·세션·시퀀스 식별자는 UI의 명시적 값으로 전달한다.
6. 기존 엔진이 만든 한국어 답변을 보존하고 본문만 대상 언어로 번역한다. UI는 번역문을 기본 표시하고 한국어 원문 확인 기능을 제공한다.
7. 실패하면 재녹음·텍스트 입력·한국어 원문 보기로 복구한다. 번역 실패를 성공한 외국어 응답으로 표시하지 않는다.

```text
마이크 → 녹음/업로드 → ASR → 원문 확인
                            ↓
                    외국어이면 한국어 번역
                            ↓
                  기존 Co-Pilot 요청/분석/RAG
                            ↓
                한국어 정본 + 구조화된 분석/근거
                            ↓
          본문 번역 또는 검수된 템플릿 → JSON → UI
                            ↓
                    선택적 후속 TTS
```

### 4.2 녹음과 브라우저 제약

입력은 최대 30초·업로드 10 MiB를 초기 제한으로 제안한다. WAV와 브라우저 WebM/Opus의 실제 디코딩을 검증하고 서버에서 mono 16 kHz PCM으로 정규화한다. 확장자만 믿지 않고 컨테이너·코덱·디코딩된 길이·샘플 수를 확인한다. 무음·손상 파일은 질의로 보내지 않는다. VAD는 보조 기능이며 주변 대화를 자동 수집하는 상시 녹음은 제외한다.

웹 마이크는 보안 컨텍스트와 사용자 권한이 필요하다. Spark의 일반 HTTP 호스트/IP로 접속해 화면이 보인다고 마이크까지 동작하는 것은 아니다. 원격 사용은 신뢰되는 HTTPS, 개발은 SSH 포워딩을 통한 사용자 PC의 `localhost`를 검증한다. Electron은 기존 샌드박스를 유지하면서 OS·앱 권한을 별도로 검증한다. 브라우저 내장 음성 인식 서비스를 로컬 ASR의 대체로 사용하지 않는다. [MDN getUserMedia](https://developer.mozilla.org/en-US/docs/Web/API/MediaDevices/getUserMedia)

## 5. 로컬 모델 조사와 선정 기준

### 5.1 언어 범위에서 주의할 점

Qwen3-ASR 공식 목록에 대상 언어 중 한국어·영어·중국어·베트남어는 있지만 우즈벡어·미얀마어·네팔어는 없다. 따라서 경량 Qwen 하나로 7개 언어를 모두 처리하는 설계는 채택하지 않는다. [공식 ASR 언어 표](https://huggingface.co/Qwen/Qwen3-ASR-0.6B)

TranslateGemma는 언어 코드가 공식 템플릿에서 허용되는지 확인하고 양방향 번역 품질을 따로 평가한다. 카드에 명시된 입력 컨텍스트는 2K 토큰이므로 한국어 본문을 토크나이저로 계산하고 문단 단위로 분할한다. 번역 중 문단 누락·중복 여부를 검사한다. 일반적인 OpenAI 채팅 템플릿을 그대로 적용하지 않는다. [TranslateGemma 입력·템플릿](https://huggingface.co/google/translategemma-4b-it)

TranslateGemma 기술 보고서 부록 B/C에는 우즈벡어·미얀마어·네팔어의 학습 언어 관련 근거가 있지만 방향별 데이터 구성이 다르다. 미얀마어는 영어→미얀마어 목록에 있으며 이것만으로 미얀마어→한국어를 보장할 수 없다. 55개 평가 언어, 추가 학습 언어, 템플릿 허용 코드, 실제 한국어 양방향 품질은 서로 구분한다. 직접 번역이 미달이면 영어 피벗을 비교하되 단계 수·오류·지연 증가를 기록한다. [TranslateGemma 보고서 부록](https://arxiv.org/pdf/2601.09012)

MADLAD-400-3B-MT도 다국어 번역 대안으로 평가한다. 공개 카드의 Apache-2.0과 Transformers 실행을 확인했으나 도장 특화 품질을 보장하지 않으며, 대상 언어 토큰·가중치·한국어 직접 번역을 실제 검증해야 한다. Hugging Face 가중치는 변환본이므로 원본 체크포인트와 출처·revision을 추적한다. [MADLAD 모델 카드](https://huggingface.co/google/madlad400-3b-mt)

TTS의 공식 10개 언어는 중국어·영어·일본어·한국어·독일어·프랑스어·러시아어·포르투갈어·스페인어·이탈리아어다. ASR 또는 번역이 가능한 언어라고 음성 출력까지 가능하지는 않다. 미지원 언어는 검수된 사전 녹음 또는 텍스트만 제공한다. 음성 복제는 MVP에서 제외한다. [Qwen3-TTS 지원 언어](https://huggingface.co/Qwen/Qwen3-TTS-12Hz-0.6B-Base)

### 5.2 대안과 트레이드오프

- **권장: 한국어 정본 + 별도 번역기.** 현재 도장 튜닝·한국어 RAG를 유지하고 번역 품질을 독립적으로 검수한다. 단점은 외국어 입력일 때 번역이 두 번 발생하고 메모리가 추가된다는 점이다.
- **비교안: 기존 27B가 바로 외국어 답변 생성.** 출력 번역 단계를 줄일 수 있으나 한국어 정본과의 의미 일치가 보장되지 않는다. 언어별 도장·안전 평가를 통과하기 전에는 기본 경로로 채택하지 않는다.
- **장기안: 다국어 질의로 직접 검색.** 검색 모델의 다국어 지원만으로 현장 용어 검색 품질을 보장할 수 없다. 입력 번역과 검색 recall을 비교한 뒤 별도 최적화한다. 기존 인덱스 재구축은 MVP 필수가 아니다.
- Ollama로 서버를 바꾸는 것만으로 ASR·번역 단계가 없어지거나 빨라지는 것은 아니다. 실행기는 모델·정밀도·언어 품질·ARM64 성능·메모리를 함께 평가해 선택한다. 기존 vLLM 교체는 이 PRD의 필수 범위가 아니다.

## 7. API 확장 제안

**아래 경로는 미구현 제안이다.** 기존 공개 API에 바로 추가하지 않고 계약 담당자 승인 후 스키마·OpenAPI·클라이언트·테스트를 함께 추가한다. 초기 실험 경로는 공개 계약에서 숨긴다.

### 7.1 음성 전사: `POST /api/v1/voice/transcriptions`

`multipart/form-data`: `audio`(파일), `user_id`, 선택적 `session_id`, `request_id`, `input_language`(명시 언어 또는 `auto`). 인증 주체와 user_id/세션 소유권을 확인한다. 서버는 임의 외부 URL을 다운로드하지 않는다.

제안 성공 응답:

```json
{
  "status": "SUCCESS",
  "code": 200,
  "message": "Transcription completed",
  "data": {
    "request_id": "VOICE-001",
    "transcript": "저도막이 뭐야?",
    "detected_language": "ko",
    "duration_ms": 2400,
    "processing_ms": 0,
    "confirmation_required": true,
    "quality_flags": [],
    "model_id": "Qwen/Qwen3-ASR-0.6B"
  }
}
```

예시의 `processing_ms: 0`은 측정값이 아니라 형식 예시다. 실제 응답에는 실측 시간을 넣는다. 자동 감지 결과를 작업자의 확정 언어로 덮어쓰지 않는다. 모델 간 비교 가능한 신뢰 확률이 없으면 `confidence`를 만들어 반환하지 않는다. 인식 불확실성은 `quality_flags`와 확인 UI로 처리한다.

### 7.2 다국어 질의: `POST /api/v1/localized/copilot/query`

기존 질의 객체를 그대로 포함하는 새로운 게이트웨이 계약을 제안한다. `query.prompt`에는 사용자가 확인한 원문을 넣고 게이트웨이가 한국어 입력 번역을 수행한다. `input_language`에는 확정 언어만 허용하며 `auto`는 전사 단계 전용이다.

```json
{
  "query": {
    "user_id": "USER-001",
    "scenario_id": "TR-L01",
    "session_id": "SESSION-001",
    "request_id": "QUERY-001",
    "prompt": "저도막이 뭐야?",
    "task_type": "knowledge_search",
    "use_rag": "Y",
    "context": null
  },
  "localization": {
    "input_language": "ko",
    "output_language": "en"
  }
}
```

최상위 응답은 `status/code/message/data` 래퍼를 유지한다. `data`의 신규 형식은 다음과 같다.

| 필드 | 내용 |
|---|---|
| `copilot` | 기존 `CopilotQueryData` 전체. `answer`는 한국어 정본, 나머지는 기존 계약 그대로 |
| `localization.input_language` / `output_language` | 확정된 요청 언어 |
| `localization.status` | `translated`, `unchanged`, `fallback_original` 중 하나 |
| `localization.answer` | 번역 성공 시 번역 본문, 동일 언어이면 원문, 실패이면 null |
| `localization.reason_code` | 성공이면 null, 실패이면 안정적인 코드 |
| `localization.translator_model_id` | 모델 사용 시 모델 ID, 템플릿/무번역이면 null |
| `localization.glossary_version` | 적용된 용어집 버전 |
| `timings` | 입력 번역·기존 질의·출력 번역·큐 대기·게이트웨이 전체의 실측 ms |

기존 `copilot.latency_ms`는 기존 질의의 시간이며 게이트웨이 전체 시간으로 덮어쓰지 않는다. 분석 컨텍스트의 자연어 설명이 필요하면 승인된 JSON 경로만 별도의 `localized_fields` 표시 맵으로 확장한다. MVP는 `answer`만 번역하며 전체 JSON을 번역기에 넣지 않는다.

### 7.3 장애 계약

- 검증 오류 422, 과대 입력 413, 미허용 미디어 415, 큐 제한 429, 신규 서비스 준비 안 됨 503은 동일 ERROR 래퍼와 `data: null`로 응답한다. 안정적 사유 코드는 문서화된 `message` 토큰으로 제공하고 UI가 현지화한다.
- 무음은 `NO_SPEECH`, 언어 미지원은 `UNSUPPORTED_LANGUAGE`. 전사 후 인식문이 4000자 제한을 넘으면 잘라 실행하지 않고 수정을 요청한다.
- **입력 번역 실패:** 기존 질의를 실행하지 않는다. 재시도 또는 명시적 한국어 텍스트 입력을 안내한다.
- **출력 번역 실패:** 기존 분석 성공 결과는 보존한다. 게이트웨이는 SUCCESS + `localization.status=fallback_original`, 번역문 null, 실패 사유를 반환한다. UI가 한국어 원문임을 알린다. 이는 기존 분석의 `degraded`를 임의 변경할 사유가 아니다.
- 기존 분석 자체가 ERROR면 그 오류를 유지하며 번역 완료처럼 표시하지 않는다. 취소된 요청은 결과를 다른 세션에 전달하지 않는다.

## 8. 번역 안전성과 도장 용어집

용어집은 언어별 원어민·도장 전문가가 승인한다. 저도막/과도막, 건조도막두께, 분사거리, 중첩률, 분사각도, 패스, 구역, 재도장 간격, 보호구 등의 기술적 의미를 포함한다. 원문 정의·승인 번역·금지 표현·버전을 관리한다. **선행 산출물은 [7개 언어 전문용어 대비표](local_voice_multilingual_terminology.md)다. 초안 작성 → 언어별 검수 → 승인 버전 고정 후 해당 언어의 모델 품질 평가·사용자 배포로 진행한다. 미검수 초안을 운영 번역 규칙으로 넣지 않는다.**

1. 숫자, 범위, 비교 연산, 단위, URL, 문서 ID, `TR-L01`, 구역 `A-1` 등의 보호 토큰을 추출한다.
2. 필요하면 플레이스홀더로 보호하고 복원 후 개수·값·단위를 검사한다. 보호 토큰 변환 자체도 언어별 품질 평가를 통과해야 한다.
3. 구조화된 JSON은 모델 밖에서 보존하며 한국어 정본과 구조적 동등성을 검사한다.
4. 누락·추가 수치나 검증 실패가 있으면 번역문을 노출하지 않는다. 자동 재시도는 최대 1회이며 전체 시간 제한 안에서만 수행한다.
5. 부정문, 금지/권고, 합격/불합격 반전은 토큰 검사만으로 잡을 수 없다. 출시 전 사람 평가와 안전 문구 템플릿이 필수다. 역번역만으로 안전성을 입증하지 않는다.
6. 인식문·검색 문서·분석 결과는 데이터다. 번역기가 도구를 호출하거나 외부 요청·세션 상태 변경을 할 권한을 갖지 않도록 격리한다.

긴 본문은 문단 경계를 유지해 번역한다. 시간 초과 시 임의 요약으로 수치·주의사항을 생략하지 않는다. 번역 캐시는 원문 해시·입출력 언어·모델 revision·용어집 버전으로 키를 만들고 세션별 민감 데이터 공유를 금지한다.

## 9. Spark 패키징과 리소스

- 기존 vLLM/MCP/agent-api/web을 유지하고 `voice-asr`, `text-translator`, 언어 게이트웨이를 선택 프로파일로 분리한다. 초기 GPU 작업은 한 번에 하나씩 허용하는 공유 admission queue를 두어 피크 메모리를 줄인다. 대기열·동시 접속 수는 명시적으로 제한한다.
- 모델은 프로세스 시작 시 한 번 로드하고 재사용한다. 요청마다 초기화하지 않는다. 로드·warm-up·언어 매핑·추론 probe가 끝나야 신규 기능을 ready로 표시한다. 텍스트 API의 준비 상태와 음성 기능의 준비 상태를 분리한다.
- Qwen3-ASR 공식 문서는 격리된 Python 3.12 환경을 권장한다. 프로젝트의 Python 3.11 개발 환경과 분리한 이미지에서 먼저 Transformers 경로를 검증한다. FlashAttention이나 ASR용 vLLM을 필수 조건으로 가정하지 않는다. [Qwen3-ASR 환경 안내](https://huggingface.co/Qwen/Qwen3-ASR-0.6B)
- faster-whisper는 성능 비교용 실행기 후보다. 공식 GPU 의존성은 CUDA 12/cuDNN 9이다. ARM64 wheel, GB10 커널, 이미지 런타임 호환성 확인 없이 Spark에서 바로 동작한다고 약속하지 않는다. `nvidia-smi`의 CUDA 13.0은 설치된 모든 라이브러리·모델 실행기의 호환 보증이 아니다. [faster-whisper 요구사항](https://github.com/SYSTRAN/faster-whisper)
- 새 이미지는 Spark 또는 검증된 ARM64 빌더에서 만든다. x86 호스트에서 만든 이미지나 패키지를 그대로 배포하지 않는다. 이미지 digest, 가중치 revision/SHA256, 토크나이저, 용어집, 라이선스, 런타임 lock을 릴리스 manifest에 포함한다.
- 읽기 전용 모델 볼륨과 내부 네트워크만 사용한다. ASR·번역 모델 포트를 사용자에게 직접 공개하지 않는다. 가중치 다운로드·라이선스 동의는 준비 단계에서 끝내고 실행 중 외부 접근을 막은 상태로 재시작 테스트한다.

### 9.1 메모리 게이트

GB10의 시스템/GPU 공유 메모리는 여러 프로세스가 함께 소비한다. 추가 모델이 작다는 이유만으로 기존 vLLM의 KV 캐시 예산을 유지한 채 무제한으로 추가하면 안 된다.

Spark에서 기존 서비스의 idle/peak, ASR과 번역 모델의 로드/활성/워크스페이스, 긴 문맥 RAG, 자세 분석, 동시 요청의 **시스템 전체 peak**를 측정한다. 필요한 경우 기존 vLLM의 GPU 메모리 비율·KV 캐시·동시 요청 상한을 재조정하되 기존 품질·문맥 길이 회귀 테스트를 함께 수행한다. 각 서비스가 독립적으로 GPU 메모리 대부분을 예약하게 두지 않는다.

출시 기준 제안은 30분 혼합 부하에서 OOM·swap thrashing·프로세스 재시작 0건, 최악 조건에서 가용 메모리 10 GiB 이상이다. 최종 안전 여유는 실측 후 운영 담당자가 승인한다. 충족하지 못하면 번역기를 기존 27B 경로와 비교하거나 단계별 모델 상주 구성을 바꾸고 다시 측정한다. 무검증 양자화나 모델 교체로 품질을 낮추지 않는다.

## 10. 지연시간 목표와 측정

**음성과 번역을 붙이는 것은 기존 RAG를 자동으로 빠르게 만들지 않는다.** 단일 최종 JSON 방식이면 출력 번역까지 끝나야 외국어 답변이 보인다. 인식문·상태 표시가 빨라져도 첫 답변이 빨라진 것과 구분한다. 기존 버퍼링 후 재분할 SSE를 실제 토큰 스트리밍으로 간주하지 않는다.

```text
음성 종료→외국어 최종 표시
  = 업로드/디코딩 + ASR + 입력 번역(필요 시)
  + 기존 질의/RAG/생성 + 출력 번역(필요 시) + 전송/렌더링 + 대기
```

측정점은 녹음 시작, 발화 종료, 업로드 완료, ASR 완료, 인식문 표시, 사용자의 확인, 입력 번역 완료, 기존 질의 완료, 번역 완료, 답변 표시다. 사용자 확인 대기와 실제 발화 길이는 시스템 처리 시간에서 분리하고 별도로 보고한다.

| 지표 | 초기 목표 제안(미실측) | 조건 |
|---|---|---|
| 녹음 버튼/처리 상태 표시 | p95 200 ms 이내 | 클라이언트 UI 반응, 답변 아님 |
| 전사 완료 | warm p95 2초 이내 | 업로드 완료 후, 10초 이하 발화, 동시 1건 |
| 번역 추가 비용 | 번역 방향별 warm p95 3초 이내 | 한국어 본문 150자 수준, 대응 외국어 길이 기록 |
| 기존 질의 영향 | 동일 텍스트 기준 p95 악화 10% 이내 | 신규 서비스 상주/혼합 부하 비교 |
| 외국어 최종 답변 | 현행 텍스트 경로와 단계별 차이 보고 | 목표 숫자는 실측 후 승인, 현재 4초 보장 없음 |

위 숫자는 제품 검증 가설이며 배포 성능을 주장하는 값이 아니다. 모델 제작자의 A100/다른 GPU throughput 수치를 Spark 단일 질문 지연시간으로 환산하지 않는다. 한국어→외국어 출력만, 외국어 음성→한국어, 외국어 음성→다른 언어를 따로 측정한다.

성능 비교는 동일 내용의 질문·동일 인덱스·답변 길이·모델 정밀도로 하고 cold/warm, 1명/2명/4명, ASR/번역 단독과 RAG 혼합 부하를 기록한다. 구성별 warm 100회 이상으로 p50/p95/max를 보고하고 품질 결과와 함께 결정한다. 지연시간 미달이면 검수된 FAQ/경고 캐시, 불필요한 입력 번역 생략, 본문 길이 제어, 모델 후보 비교를 우선한다. 실제 답변 스트리밍은 별도 승인된 확장 계약에서 추진한다.

## 11. 보안·개인정보·운영

- 로컬은 사용자의 PC에서 녹음하고 **Spark에서 추론**한다는 뜻이다. 음성과 텍스트를 외부 AI 서비스로 보내지 않는다. 인터넷 차단 시험과 외부 요청 관측으로 검증한다.
- 음성은 요청 처리 후 삭제한다. 초기 임시 파일 최대 보존은 5분이며 취소·예외·재시작 후 정리도 시험한다. 운영 로그에는 원음·인식문·전체 답변을 기본 기록하지 않는다.
- 음성 평가 데이터 수집은 별도 동의, 접근 권한, 암호화, 보존 기간이 승인된 경우에만 수행한다. 음성 복제·화자 식별·생체 인증은 제외한다.
- 기존 인증·세션 권한을 신규 경로에 적용한다. 파일 디코더에는 시간·CPU·메모리 상한을 두고 마이크 권한 거부 시 텍스트 입력을 유지한다.
- ASR·번역 장애 시 feature flag로 신규 경로만 끄고 기존 텍스트·한국어 API로 롤백한다. 한국어 원문과 번역 성공/실패 상태는 UI에서 구별한다.

## 12. 품질 평가 및 출시 게이트

다음 기준은 언어별 출시 기준 제안이다. 지원 국가 확정 후 도장 전문가·해당 언어 검수자가 수치와 테스트셋을 승인한다. 언어별 합격을 전체 평균으로 대체하지 않는다.

| 영역 | 테스트 / 합격 기준 제안 |
|---|---|
| 전사 | 언어별 최소 100발화·5명, 학습/튜닝과 분리된 화자. 실제 헤드셋·작업 소음·억양·혼합 언어·무음 포함 |
| ASR 정확도 | 언어에 맞는 정규화와 WER/CER 정의를 고정. 한국어 CER ≤10%를 초기 목표로 평가하고 외국어는 언어별 기준 승인 후 출시 |
| 중요 토큰 | 숫자/단위/구역/부정어가 있는 발화를 별도 채점. 중요 토큰 정확도 ≥99% 목표, 오류 발화는 사용자 확인으로 차단되는지 시험 |
| 번역 품질 | 언어쌍별 최소 200문장, 양방향 별도 평가. 기술 의미·자연스러움 5점 척도 평균 ≥4, 중요 문구는 전문가 합의 |
| 안전 | 금지/권고·합부·임계값 반전 시험 최소 100건. 심각한 의미 반전·허위 안전 승인 0건, 발생 언어는 출시 차단 |
| 계약 | 기존 요청 예시 유효성, extra 금지, 전체 분석 컨텍스트/ID/enum/수치/null/citations 보존 100% |
| 실패 | 무음·권한 거부·손상 파일·과대 입력·언어 미지원·모델 장애·대기열 포화·취소·긴 본문·번역 보호 토큰 손상 |
| 로컬 실행 | 인터넷 차단 후 전체 흐름 성공, 임시 원음 삭제, 클라우드 요청 0건 |
| 운영 | §9 메모리와 §10 지연시간 실측, 텍스트 경로 회귀 없음, 한국어 롤백 성공 |

종단 평가에는 “저도막이 뭐야?”, “A-1 구역의 80 µm는 합격인가?”, 부정문·재도장 간격·분사거리·준비 중 기능 안내·근거 부족 답변을 포함한다. 정답 수치나 판정은 번역 평가를 위해 임의로 만들지 않고 기존 문서/엔진의 결과를 정본으로 사용한다.

## 13. 단계별 실행 산출물

| 단계 | 작업 | 완료 조건 |
|---|---|---|
| 0: 용어집 선행 | 확정 7개 언어의 전문용어 대비표, 문자/방언, TTS 여부, 원음 정책 | 대비표 초안 작성 후 언어별 도장 전문가·원어민 검수. 평가 정답과 운영 용어집 승인 |
| 1: Spark 탐색 | 공통 Whisper/일부 언어 ASR 0.6B, 번역 4B/MADLAD 3B/기존 27B의 isolated 이미지·로컬 가중치·GB10 추론 | 언어 coverage, 라이선스, ARM64, 메모리, 품질·지연 리포트. 실패 후보 제외 |
| 2: 한국어 음성 입력 | 마이크→전사→수정/확인→기존 질의 | 텍스트 동작 보존, 무음/권한/취소 시험, 한국어 전사 게이트 |
| 3: 다국어 텍스트 출력 | 신규 계약 승인, 본문 번역·용어집·검수 템플릿·폴백 | 언어별 출력 평가, 수치/계약 보존, 전체 JSON 완료시간 실측 |
| 4: 외국어 음성 입력 | 입력 번역·언어 매핑·다언어 UI | 양방향 언어쌍 평가. 합격 언어만 기능 활성화 |
| 5: 선택적 TTS | 지원 언어 음성 합성 또는 사전 녹음, 자막·재생 제어 | 별도 동의/라이선스/발음/지연 게이트. 미지원 언어에 음성 출력 약속 금지 |

구현 시 Python 경계는 Pydantic, UI 경계는 Zod로 검증하고 대응 계약을 함께 갱신한다. Python 테스트는 `ship-paint-trainer` 컨테이너에서 실행하고 프런트엔드는 `demo-ui`의 `build:web`, `npm test`, 실제 마이크 브라우저 시험을 수행한다. ASR/번역 추론은 Spark의 별도 런타임에서 검증한다. 이 PRD 작성 단계에서는 모델 설치나 서비스 변경을 수행하지 않았다.

## 14. 결정이 필요한 항목

1. **D1 / 사업 담당자:** 지원 7개 언어는 확인 완료. 중국어 문자·방언과 우즈벡어 문자·지역 태그의 세부 범위는 확인 필요.
2. **D2 / 제품 담당자:** MVP 출력은 외국어 텍스트만인지, 음성 재생까지 필수인지. 기본 제안은 텍스트 우선이다.
3. **D3 / 계약 담당자:** 신규 경로·래퍼·언어 설정 소유권·오류 코드 승인. 현행 v2.5 변경은 금지한다.
4. **D4 / 운영 담당자:** 예상 동시 사용자·음성 길이·허용 최종 응답시간·Spark 메모리 예산. 실측 후 SLO 확정.
5. **D5 / 언어 검수 담당자:** 언어별 도장 용어집, 안전 문구, 품질 기준, 승인자.
6. **D6 / 보안·라이선스 담당자:** 원음 보존 정책, Gemma 이용조건과 릴리스 재배포 조건 검토.

이 문서의 완료는 조사·요구사항 정리의 완료를 뜻한다. 전문용어 승인, 신규 API 승인, 모델 품질 통과 또는 Spark 배포 완료를 뜻하지 않는다.
