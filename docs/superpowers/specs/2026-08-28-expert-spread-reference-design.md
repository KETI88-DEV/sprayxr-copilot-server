# 숙련자 실측 산포 레퍼런스 설계

**Date**: 2026-08-28
**Status**: Draft (design) — 구현 전
**Scope**: 임시 상수 0.05 m를 실측 산포로 대체해 σ·REQ-19 게이트·개선율을 의미 있게 만든다. 자세 비교 실험대의 모든 headline 숫자가 여기에 걸려 있고, 납품 지표(개선율 70%)의 달성 여부도 여기서 판가름난다.

**관련 문서**: [`2026-08-28-pose-lab-design.md`](2026-08-28-pose-lab-design.md) (이 설계가 얹히는 도구), `goal_year2.md` (개선율 70% 목표), [`dataset_spec.md`](../../dataset_spec.md), [`data_requirements_pose_sequence_mcp.json`](../../data_requirements_pose_sequence_mcp.json) v3.1 (REQ-19 게이트)

---

## 1. 목표 / 비목표

### 목표

- **잣대를 실측으로 만든다.** 지금 σ와 점수와 게이트가 모두 근거 없는 상수 0.05 m로 정규화돼 있다.
- **`improvement.split`을 실제로 계산한다.** 지금은 `null`이고, 그래서 향상 중 얼마가 자기충족인지 알 수 없다.
- **교정 선택을 "가장 큰 것"에서 "가장 이상한 것"으로 바꾼다.**
- **70% 목표에 대한 답을 숫자로 낸다.** 납품 문구대로 재면 몇 %, 정직하게 재면 몇 %인지.

### 비목표

- **각도 기준.** 2026-08-28 측정으로 기각됐다(§2.3). 이 설계는 위치만 다룬다.
- **훈련생 코호트.** REQ-16은 미확보다. 타 작업자 5인이 대용이며 훈련생이라 주장하지 않는다.
- **표시용 스켈레톤.** 검증된 FK 경로가 없다(BVH가 다른 IK 솔버). 별건이다.
- **발주처 대응 결정.** §10의 표를 산출할 뿐, 목표 미달을 어떻게 다룰지는 사용자 판단이다.

## 2. 배경 — 실측으로 확인된 것

### 2.1 잣대가 상수였다

`trainer/pose_lab/service.py`의 `PROVISIONAL_SPREADS`는 `{right: 0.05, head: 0.05, left: 0.05}`다. 이 값이 σ를 정규화하고, σ가 점수 `exp(−σ²/2)`를 만들고, 같은 상수가 REQ-19 게이트의 `s`로 들어간다. 게이트는 `0.05/0.144 = 0.347 < 0.5`이라 **항상 통과**했고, 그래서 현재는 `gate: null` + `normalization: "provisional"`로 비워 둔 상태다.

### 2.2 개선율은 항등식이었다

옛 `apply_measured`는 세 점을 각자의 평균 편차만큼 옮겼다. 평균 편차가 정의상 0이 되므로 `exp(−σ²/2) = 1.0`이다. 측정이 아니라 항등식이었다.

교정을 실제로 내준 지시 하나로 좁힌 뒤 실측:

| 비교 쌍 | 이전 | 이후 |
|---|---|---|
| 손영석 p135 ↔ 전형기 p75 | 1.0000 | 0.0275 |
| 전형기 p110 ↔ 손영석 p168 | 1.0000 | 0.0004 |
| 무작위 60쌍 중앙값 | 1.0000 | 0.0007 |

**단 이 수치도 임시 정규화 위에서 나온 값이라 진짜 미달 폭이 아니다.** 실측 산포를 넣어야 의미를 갖는다.

### 2.3 각도는 기각됐다

건 방향의 쿼터니언 측지 산포 중앙값이 41.4°이고 게이트 기준 15°의 2.8배다. 게이트 통과 커버리지 4.3%(사전등록 기준 50%). 스트로크 프레임으로 옮기면 오히려 악화(70.6°). 산포의 91%가 한 작업자의 반복 변동이다. **숙련자 본인이 그만큼 흔들리므로 그들의 반복으로 만든 어떤 각도 기준도 그보다 좁을 수 없다.**

이 설계가 위치만 다루는 이유다. 위치는 아직 같은 검정을 받지 않았다.

### 2.4 버킷은 충분하다

실측 요를 넣은 뒤 6인 479세션 64,098패스 기준:

| 지표 | 값 |
|---|---|
| 서로 다른 키 | 4,709 |
| 최대 버킷 | 322 |
| 쓸 수 있는 키(n≥20, 작업자 ≥2) | 887 |
| 커버리지 | 71.6% |

초기에 나온 "키당 3.3개"는 12세션만 본 인공물이었다. 표본은 문제가 아니다.

다만 **이 수치는 6인 전체 기준**이다. 전형기 혼자로는 훨씬 적으며, 그 실측이 §6 폴백의 필요성을 결정한다.

## 3. 핵심 결정

### D1. 산포는 전형기 한 사람의 변동으로 잰다

`goal_year2`가 전형기 반장을 표준으로 지정한다. 6인 전체로 산포를 재면 **작업자 간 차이가 `s`에 들어가는데, 그것이 바로 교정하려는 대상**이다. `s`가 커지면 모든 자세가 정상 범위로 보이고 교정이 나가지 않는다.

측정된 근거도 있다. 건 각도 산포 분해에서 작업자 간 성분이 전체의 0.35배였다 — 6인 풀링은 잣대를 눈에 띄게 넓힌다.

대가는 커버리지다. 전형기는 79세션뿐이라 887개 버킷을 채우지 못한다. §6의 폴백이 그 대가를 관리한다.

### D2. 산포는 축별로 잰다

편차는 스트로크 프레임에서 3차원(벽 법선 / 진행 방향 / 수직)인데 현행 `spreads`는 점당 스칼라 하나다. 그리고 교정문은 **raw 크기가 가장 큰 성분**을 고른다.

전형기의 벽 거리가 3 cm로 일정하고 진행 방향이 20 cm로 느슨하다면, "진행 방향 17 cm"는 정상이고 "벽에서 5 cm"가 비정상이다. **가장 큰 것과 가장 이상한 것은 다르다.** 축별 산포로 재고 σ가 최대인 축을 고른다.

표본 수는 그대로다. 같은 패스에서 분산을 셋으로 나눌 뿐이다.

### D3. 질의가 전형기 자신이면 그 날짜를 레퍼런스에서 뺀다

자기가 자기 평균에 가까운 것은 당연하다. 타 작업자 질의는 겹침이 없으므로 전체를 쓴다.

### D4. `improvement`는 분리 채점과 동일 채점을 둘 다 낸다

전형기가 5개 날짜를 가지므로 날짜를 겹치지 않는 두 그룹으로 갈라 **교정용 레퍼런스 A**와 **채점용 레퍼런스 B**를 만들 수 있다. 이제껏 `null`이던 `improvement.split`이 실제 값을 갖는다.

`same`은 교정에 쓴 분포로 다시 채점하므로 향상이 정의상 보장된다. `split`이 있어야 그 향상 중 얼마가 자기충족인지 드러난다. `goal_year2`의 문구는 목표 자세를 입력으로 주므로 `same`에 해당한다 — **둘을 병기해야 납품 기준을 만족시키면서 그 값이 무엇에 기대는지도 함께 보인다.**

### D5. 충분 표본 기준 `n ≥ 20`은 이전 연구값을 그대로 쓴다

이번에 숫자를 보고 정하지 않는다. REQ-19에서 "납품 후 수치를 보고 기준을 옮기지 말자"고 세운 규율을 따른다.

## 4. 레퍼런스 아티팩트

전형기 학습모드(레벨 1~10, `1-A`/`1-B`/`1-C` 제외) 패스만으로 만든다. CLI가 `/output`에 JSON을 쓴다. 기존 `build_pose_reference.py`의 산출 패턴을 따른다.

값은 **미터 단위 위치**이므로 산술 평균·표준편차로 충분하다. `dataset_spec.md` §4.1의 순환 통계 요구는 오일러 각에 대한 것이고 여기에는 적용되지 않는다.

구조:

```
{ "version", "worker": "전형기", "levels": [...], "built_at",
  "sessions": int, "n_min": 20,
  "granularities": {
    "uv8": { "<motion_key>": {
        "n": int,
        "dates": ["YYYYMMDD", ...],
        "by_date": { "YYYYMMDD": { "n": int, "sums": {...}, "sq_sums": {...} } },
        "points": { "right"|"head"|"left": {
            "wall"|"vertical"|"lateral": { "mean": float, "spread": float } } } } },
    "uv4": {...}, "uv2": {...}, "uv_off": {...} } }
```

축 이름은 `stroke_frame.Basis`의 `normal`/`tangent`/`up`이 아니라 `measured_score._correction_candidates`가 내는 `wall`/`vertical`/`lateral`을 쓴다. 산포를 재는 축과 교정을 고르는 축이 같아야 σ 하나로 "이 편차가 이 축에서 얼마나 이상한가"를 물을 수 있다 — 이름이 갈리면 산포 테이블을 만들어도 교정 축을 고르는 쪽이 그 값을 찾을 수 없다.

네 입도 층을 한 아티팩트에 담는다. 거리 분할(near/far)은 모든 층에서 유지한다.

**날짜별 부분합(`by_date`)을 함께 싣는다.** D3의 날짜 제외와 D4의 A/B 분리를 전수 재빌드 없이 하려면 필요하다. 합과 제곱합을 담으면 임의의 날짜 부분집합에 대해 평균과 산포를 재구성할 수 있다.

---

## 5. 자기충족 차단

두 곳에서 작동한다.

**채점 시(D3)**: 질의가 전형기의 날짜 `d`에서 온 패스면, `by_date`에서 `d`를 뺀 부분합으로 평균과 산포를 재구성해 쓴다.

**개선율 산출 시(D4)**: 전형기의 날짜를 겹치지 않는 두 그룹 A(교정용)와 B(채점용)로 나눈다. 질의가 누구냐에 따라 필요한 날짜 수가 다르다.

- **타 작업자 질의**: 질의가 전형기 날짜를 전혀 쓰지 않으므로 A·B 2분할로 충분하다. 버킷에 전형기 날짜가 2개 이상 있으면 성립한다.
- **전형기 자신의 질의**: 질의 날짜가 A에도 B에도 들어가면 안 되므로 3분할이 필요하다. 버킷에 날짜가 3개 이상 있어야 성립한다 — `eval_pose_correction.py`가 이미 쓰는 규약과 같다.

날짜가 모자라 해당 분할이 불가능한 버킷에서는 `split`을 `null`로 두고 사유(`insufficient_dates`)를 응답에 적는다. **없는 값을 만들어내지 않는다.**

---

## 6. 입도 폴백

`uv8`에서 `n ≥ 20`이면 쓴다. 미달이면 `uv4 → uv2 → uv_off` 순으로 내려가 처음 충족하는 층을 쓴다. 전부 미달이면 `unavailable`이다.

응답과 화면에 **어느 층에서 표본 몇 개로 나온 값인지** 반드시 표시한다. 같은 화면의 두 숫자가 서로 다른 입도에서 나올 수 있고, 그 사실이 보이지 않으면 비교가 거짓이 된다.

폴백은 의도가 덜 비슷한 동작을 섞는다. 그것이 대가이며, 표시가 그 대가를 드러내는 장치다.

---

## 7. 교정 선택 변경

`corrections_text`가 σ가 최대인 축을 고른다. 오른손 한 문장, 성분 하나라는 현행 규약은 유지한다. **각도는 여전히 내지 않는다** — §2.3에서 기각됐고 REQ-19 게이트도 미통과다.

## 8. 응답에서 바뀌는 것

| 필드 | 현재 | 이후 |
|---|---|---|
| `measured.normalization` | `"provisional"` | `"measured"` |
| `measured.gate` | `null` | 실제 판정 |

`joint` 축은 그대로 리터럴만 담는다(`status: "not_wired"`). 실측 축 값을 빌려오지 않는다.

## 9. 검증

| 대상 | 방법 | 통과 조건 |
|---|---|---|
| 기준선 | 컨테이너 전체 스위트 | 548개 유지 |
| 자기충족 | 같은 입력에서 `split`과 `same` 비교 | `split ≤ same` |
| 분리 규약 | 교정용·채점용 레퍼런스를 같게 설정 | `same`이 재현된다 |
| 날짜 제외 | 전형기 자기 패스를 질의로 | 그 날짜가 실제로 빠진다 |
| 부분합 재구성 | 날짜 제외 결과 vs 그 날짜 없이 전수 빌드 | 평균·산포가 일치한다 |
| 폴백 | 얇은 버킷 질의 | 층이 내려가고 응답에 표시된다 |
| 축별 선택 | 큰 raw + 작은 σ / 작은 raw + 큰 σ | 후자를 고른다 |

**그리고 §10의 표를 산출한다.** 이것이 이 설계의 최종 산출물이다.

## 10. 70% 질문에 대한 답을 내는 방식

여러 비교 쌍에 대해 개선율 분포를 낸다. 다음을 보고한다.

- 쌍의 수와 선정 방식(무작위 표집인지 전수인지)
- `same`의 중앙값·사분위, 70% 이상인 비율
- `split`의 중앙값·사분위, 70% 이상인 비율
- 입도 층별 분해 — 굵은 층에서 나온 값이 얼마나 되는지
- 위치에 대한 REQ-19 게이트 통과 버킷 비율

**숫자를 보기 전에 이 표의 형식을 고정한다.** 결과가 나온 뒤 유리한 절단이나 부분집합을 고르지 않는다.
