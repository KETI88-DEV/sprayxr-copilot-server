# UV 도포순서 레퍼런스 기반 경로 코칭 설계

**Date**: 2026-08-03
**Status**: Draft (design) — 구현 전
**Scope**: 같은 작업면을 서로 다른 궤적으로 칠했을 때 코파일럿이 "순서"를 코칭할 수 있게 한다. 판정 근거를 불변식(규범)과 숙련자 레퍼런스(처방)로 분리하고, 레퍼런스를 단일 궤적이 아니라 UV 도포순서 필드로 만든다.

---

## 1. 목표 / 비목표

### 목표
- 방향이 다른 두 궤적을 **"틀림"이 아니라 "유효한 대안"으로 구분**할 수 있다.
- 순서 판정이 "내 리스트와 다르다"가 아니라 **위반한 제약을 지목**한다.
- 숙련자 레퍼런스를 **경로 세부에 불변인 표현**으로 만든다. 8세션을 점별 평균해 아무도 칠하지 않은 경로를 만들지 않는다.
- 레퍼런스의 **근거 강도를 산출물에 명시**한다. 1인 데이터를 규범처럼 쓰지 않는다.

### 비목표
- **학습모드의 zone 단위 순서.** Map01 하나뿐이라 zone 순서 개념이 성립하지 않는다(§2.3). 실전모드 WBTK1(Map01~07)에서만 성립하며 별도 spec으로 다룬다.
- 기존 `POST /sequence_validation/validate`(zone 단위) 계약 변경. 그대로 둔다.
- `AgentPipeline.run()` 동작 변경. 평가 경로는 고정한다.
- 실시간 Unity 연동. 본 설계는 오프라인 CSV 궤적과 `/api/sim/*` 텔레메트리 양쪽에서 동작하는 순수 함수를 정의한다.
- 두께맵(Height PNG) 기반 결함 귀속. 후속이며, §8의 검증에만 참고로 쓴다.

## 2. 배경 — 실측으로 확인된 것

2026-08-03 기준, `data/sources/professionals/` 직접 계측.

### 2.1 확보된 숙련자 데이터

| 항목 | 실측값 |
|---|---|
| 작업자 | **전형기 1인** (2026-08-03 시점. `readme.md`의 "전문가 6인" 중 1인만 디스크에 존재 — 나머지 5인은 2026-08-04 확보, §9·§11) |
| 세션 | 5일자 / CSV **100개** |
| 레벨당 반복 | **7~8회** (학습모드 `1`~`10`, 실전모드 `1-A`/`1-B`/`1-C` 각 7회) |
| 도포 패스 | 파일 접미사가 전부 `_1`. 2차 도포(320µm) 시퀀스가 별도 파일로 존재하지 않는다 |
| 텍스처 | Map01 **2048 × 2048**, 세션마다 `_Height`/`_Normal`/`_Defect` PNG 동반 |

레벨 10(8세션) 프레임 통계: ray hit 6,049~8,793 프레임, 소요 106~162초, UV 점유 범위 u[14, 1772] × v[32, 2004].

### 2.2 궤적은 재현되지 않는다 — 레퍼런스를 '선'으로 만들 수 없는 이유

같은 작업자, 같은 레벨 10, 8세션의 시작·종료 UV:

| 세션 | 시작 UV | 종료 UV |
|---|---|---|
| 1000451 | (1447, 850) | (97, 1987) |
| 1000573 | (1757, 1148) | (1703, 1198) |
| 1000588 | (1474, 862) | (516, 34) |
| 1000601 | (1758, 1190) | (1421, 1909) |
| 1000774 | (377, 412) | (1752, 1334) |
| 1000787 | (1762, 1136) | (1391, 34) |
| 1000800 | (1765, 1154) | (1453, 1970) |
| 1000813 | (1754, 1147) | (1729, 1301) |

- **시작점은 부분적으로 습관이다**: 5/8이 (1754~1765, 1136~1190)에 몰린다. 2/8이 (1447~1474, 850~862), 1/8이 (377, 412).
- **종료점은 8세션 전부 다르다.** 그런데 UV 점유 범위는 매 세션 거의 전면이다.

즉 **같은 사람이 같은 면을 매번 다른 순서로 덮는다.** 궤적을 호길이로 정규화해 점별 평균하면 실제로 존재하지 않는 경로가 나오고 분산만 커진다. 질문의 전제("사람마다 궤적이 다르다")는 1인 내부에서도 이미 성립한다.

### 2.3 중력 불변식은 기각됐다

세션별 스피어만 순위상관(도포 시각 대 값), 400점 다운샘플:

| 세션 | ρ(t, world Z) | ρ(t, UV V) |
|---|---|---|
| 1000451 | **−0.159** | +0.819 |
| 1000573 | +0.155 | +0.654 |
| 1000588 | **−0.164** | +0.782 |
| 1000601 | +0.039 | +0.642 |
| 1000774 | −0.109 | +0.522 |
| 1000787 | +0.138 | +0.636 |
| 1000800 | +0.084 | +0.661 |
| 1000813 | +0.141 | +0.575 |

- **world Z(높이)와 도포 순서는 무상관이다** (−0.16 ~ +0.16). Z 실범위는 −0.15~1.46 m로 넓은데도 그렇다. 숙련자는 위에서 아래로 내려오며 칠하지 않는다. 앞선 논의에서 세웠던 "중력/오버스프레이 낙하" 불변식은 **이 데이터에서 기각한다.**
- **UV V축 진행은 8/8 세션에서 일관되게 양수다** (+0.52 ~ +0.82). 경로는 매번 달라도 "V가 커지는 쪽으로 전진한다"는 큰 흐름은 유지된다. 이것이 실측으로 확인된 유일한 순서 규칙성이다.

V축이 물리적으로 어느 방향인지는 아직 모른다. 벤더가 Map 번호 ↔ 작업면 매핑을 미제공 상태이며(`sources/professionals/readme.md` 3항, "추후 다시 전달"), 이 매핑 없이 "위→아래"라고 서술하면 근거 없는 주장이 된다. §9에 차단 항목으로 남긴다.

## 3. 핵심 결정

### D1. 규범과 처방을 분리한다

| 객체 | 역할 | 출처 | 어조 |
|---|---|---|---|
| **불변식** | 합·불 **판정** | 시방서/문서 RAG + 결함 상관 | "위반입니다" |
| **레퍼런스** | **권장**·시연 | 숙련자 세션 분포 | "숙련자는 이렇게 합니다" |

레퍼런스를 판정에 쓰지 않는다. 이 둘을 합치면, 불변식을 모두 지키고 다른 경로로 칠한 훈련생이 매번 "틀렸다"는 말을 듣는다. 애초에 이 설계가 해결하려는 문제가 그것이다.

§2.3의 V축 진행 규칙성은 **처방으로 분류한다.** 8/8 일관이지만 1인 데이터이고, 이를 어겼을 때 품질이 나빠진다는 근거가 아직 없다. 규범으로 승격하려면 시방서 근거나 결함 상관(§8-3)이 필요하다.

### D2. 레퍼런스는 궤적이 아니라 τ-필드다

UV 평면을 격자로 나누고, **셀마다 "언제 처음 덮였는가"의 분포**를 저장한다.

```
τ(cell) = (해당 셀이 처음 도포된 시각 − 첫 분사 시각) / (마지막 분사 시각 − 첫 분사 시각)   ∈ [0, 1]
```

- 경로의 세부(지그재그 방향, 왕복 횟수, 이동 속도)에 **불변**이고, 순서 정보는 **보존**한다.
- §2.2의 문제를 피한다. 평균 내는 대상이 경로가 아니라 셀별 스칼라라서, 결과가 항상 실재하는 도포 순서를 나타낸다.
- 질문의 두 궤적을 정확히 구분한다. "우상단→아래"와 "좌하단→우측"은 τ-필드가 다르다.

정규화 축을 앞선 논의의 호길이에서 **최초도포 시각**으로 바꾼다. 호길이는 경로 평균을 전제하는데 §2.2가 그 전제를 깼다.

### D3. 근거 강도를 산출물에 박는다

`reference_quality`를 확장한다. 기존 `_select_sessions()`의 `"expert"` / `"proxy"`에 더해:

- `"single_worker"` — 작업자 1인. 소비자는 이를 규범으로 제시해선 안 된다. (2026-08-04 6인 확보로 패스 레퍼런스는 `multi_worker`가 됐다 — §11.1)
- `"multi_worker"` — 2인 이상.

`worker_count`를 함께 싣는다. 코칭 문안 생성기가 이 값을 읽어 어조를 바꾼다(§6).

## 4. 레퍼런스 아티팩트

`build_expert_reference.py`에 세 번째 산출물 `expert_path_reference.json`을 추가한다. 기존 `expert_pose_reference.json` / `expert_flow.json`은 건드리지 않는다.

```json
{
  "level": "10",
  "status": "ok",
  "reference_quality": "single_worker",
  "worker_count": 1,
  "session_count": 8,
  "uv_space": { "width": 2048, "height": 2048, "grid": 32 },
  "entry_cells": [
    { "cell": [27, 17], "frequency": 3 },
    { "cell": [27, 18], "frequency": 2 },
    { "cell": [22, 13], "frequency": 1 },
    { "cell": [23, 13], "frequency": 1 },
    { "cell": [5, 6], "frequency": 1 }
  ],
  "cells": [
    { "cell": [27, 17], "tau_mean": 0.04, "tau_std": 0.03, "n": 8, "coverage_ratio": 1.0 }
  ],
  "v_progression": { "rho_mean": 0.661, "rho_min": 0.522, "rho_max": 0.819, "n": 8 }
}
```

- `grid`는 축당 셀 개수(기본 32 → 셀 64텍셀). 설정값이며 아티팩트에 기록해 소비자가 재격자화하지 않게 한다.
- `coverage_ratio` = 해당 셀을 도포한 세션 비율. 1.0 미만이면 그 셀은 필수 영역이 아니다.
- `n < 2`인 셀은 `tau_std`를 `null`로 두고 비교에서 제외한다.
- `entry_cells`는 격자 경계에 민감하다. 위 값은 §2.2의 실제 시작점 8개를 `grid: 32`(셀 64텍셀)로 계산한 결과이며, 육안으로 한 덩어리인 5세션이 `[27,17]` 3회와 `[27,18]` 2회로 갈린다. 따라서 시작점 비교는 셀 완전일치가 아니라 **8방향 이웃 허용**으로 한다(§5).
- 세션이 `MIN_SESSION_COUNT` 미만이면 기존 `_insufficient_payload()`와 같은 모양으로 `status: "insufficient_data"`를 낸다.

레벨 키는 원본 파일명 기준(`"1"`~`"10"`, `"1-A"`~`"1-C"`)을 쓴다. `TR-L01`은 데모 식별자이며 원본 레벨과의 매핑이 아직 없다(§9).

## 5. 판정

MCP `sequence_validation` 라우터에 엔드포인트를 **추가**한다. 기존 `/validate`는 그대로다.

```
POST /sequence_validation/path
```

**요청**

```json
{
  "level": "10",
  "tau_field": [ { "cell": [27, 17], "tau": 0.02 } ],
  "revisit_cells": [ { "cell": [12, 9], "visits": 3 } ],
  "uncovered_cells": [ [3, 30] ]
}
```

원시 궤적이 아니라 **집계된 τ-필드를 받는다.** 세션당 6천~9천 프레임이라 모델이 생성하는 도구 인자에 궤적을 실을 수 없다. 집계는 데모 API가 텔레메트리에서 수행해 `environment`에 실어 보내고, 모델은 그대로 전달한다. 기존 `zone_map`/`current_zone_id` 전달 방식과 같은 패턴이다.

**응답**

```json
{
  "verdict": "valid_alternative",
  "invariant_violations": [
    { "kind": "revisit", "cell": [12, 9], "visits": 3, "detail": "3회 재도포 — 과도막 위험" }
  ],
  "path_divergence": {
    "tau_rho": 0.41,
    "entry_match": false,
    "top_deviations": [
      { "cell": [5, 28], "tau": 0.12, "reference_tau_mean": 0.83, "delta": -0.71 }
    ]
  },
  "reference_quality": "single_worker",
  "worker_count": 1,
  "message": "..."
}
```

**verdict 3단**

| verdict | 조건 |
|---|---|
| `violation` | `invariant_violations`가 비어있지 않다 |
| `valid_alternative` | 위반 없음. 단 `tau_rho`가 임계 미만이거나 `entry_match: false` |
| `pass` | 위반 없고 레퍼런스 포락선 안 |

`tau_rho`는 훈련생과 레퍼런스가 **공통으로 가진 셀**에 대한 `tau` 대 `tau_mean`의 스피어만 순위상관이다. `entry_match`는 훈련생의 최초 도포 셀이 `entry_cells` 중 `frequency ≥ 2`인 셀 **또는 그 8방향 이웃**에 포함되면 참이다. 완전일치를 쓰지 않는 이유는 §4에 있다.

**불변식 (규범, 현 단계 채택분)**

1. **재도포(revisit)** — 같은 셀 방문 횟수가 임계 초과. 과도막 직결.
2. **미도포(uncovered)** — 레퍼런스에서 `coverage_ratio == 1.0`인 셀이 훈련생 τ-필드에 없다.
3. **wet edge** — 인접 셀 간 `|Δτ|`가 임계 초과인데 UV상 인접. 즉 옆 lane을 한참 뒤에 이어붙였다.

셋 다 결과(두께)와 직접 연결되고 방향과 무관하다. 그래서 규범이 될 자격이 있다. 임계값은 §9에서 다룬다.

## 6. 코칭 문안

`reference_quality`에 따라 어조가 갈린다. 이것이 D3의 실효다.

| verdict | `single_worker` | `multi_worker` |
|---|---|---|
| `violation` | "(12,9) 구간을 3회 재도포했습니다. 과도막 위험이 있습니다." (동일) | 동일 |
| `valid_alternative` | "진행 방향 자체는 문제가 없습니다. **참고로 숙련자 1인의 8회 기록에서는** 우측 상단에서 시작하는 경우가 5/8이었습니다." | "숙련자 6인 중 5인이 우측 상단에서 시작합니다." |
| `pass` | "숙련자 기록과 같은 순서로 진행 중입니다." | 동일 |

`violation`에서만 단정형을 쓴다. `valid_alternative`는 관찰 보고이며 교정 지시가 아니다.

## 7. 함께 고칠 것

[`sim_session.py`](../../../trainer/demo_api/sim_session.py)의 `runtime()`:

```python
index = state.recommended_flow.index(target_zone_id)
current_zone_id = target_zone_id
completed = state.recommended_flow[:index]      # ← 소급 단정
```

권장 순서상 뒤쪽 구역으로 이동하면 **건너뛴 구역을 칠했다고 조작한다.** 비선형 경로를 허용하겠다는 것이 이 설계의 전제이므로 이 줄은 전제와 정면 충돌한다. 실제 방문한 구역만 `completed`에 누적하도록 고친다. 회귀 테스트: 순서를 건너뛴 이동 후 건너뛴 구역이 `completed`에 없어야 한다.

## 8. 검증

1. **τ-필드 빌더 단위 테스트** — 합성 궤적(좌→우 래스터, 우→좌 래스터, 나선)으로 τ-필드를 만들고 셀 순서가 기대와 일치하는지 확인한다. 두 반대 방향 궤적의 `tau_rho`가 음수로 나와야 한다.

2. **Leave-one-out (핵심 게이트)** — 레벨 10의 8세션 중 1개를 훈련생으로 두고 나머지 7개로 레퍼런스를 만든다. 8번 반복한다.
   - **숙련자 자기 자신이 `violation`으로 나오면 불변식 임계값이 과하다.** 8/8이 `violation`이 아니어야 한다.
   - `pass` 대 `valid_alternative` 비율은 그대로 기록한다. §2.2대로라면 상당수가 `valid_alternative`로 나올 것이고, 그것이 정상이다. 전부 `pass`가 나오면 포락선이 너무 헐거운 것이다.

3. **결함 상관 (불변식 승격 근거)** — 세션별 `Map01_*_Height.png`를 디코딩해(`(R/255 + G/255²) × 2,000,000 × 0.01` → µm, 벤더 확인 완료) 저도막/과도막 픽셀과 `revisit`/`uncovered` 셀의 위치 상관을 본다. 상관이 확인된 불변식만 규범으로 유지하고, 확인되지 않으면 처방으로 강등한다.

4. `pytest trainer mcp_servers -q` 컨테이너 실행. `mcp_servers`는 `pyrightconfig.json` 범위 밖이라 정적 검사가 없으므로 테스트로만 덮인다.

## 11. 구현 기록 (2026-08-04, 커밋 `3ce5920`)

### 11.1 구현된 것 — 패스 궤적 축

**이 문서 §3 D2의 τ-필드(도포순서 축)는 아직 구현되지 않았다.** 먼저 구현한 것은 그 전제인
**패스 분할과 스트로크 형태 축**이다. 두 축은 서로 대체하지 않는다 — τ-필드는 "면을 어떤
순서로 덮었나", 패스 지표는 "스트로크를 어떻게 그었나"를 본다.

| 모듈 | 역할 |
|---|---|
| `trainer/scripts/pass_segmentation.py` | 버스트 → 패스 분할, 지표 산출, 버킷 키 |
| `trainer/scripts/build_pass_reference.py` | 6인 CSV → 버킷별 분포 (`expert_pass_reference.json`) |
| `trainer/scripts/pass_coaching.py` | 지표별 σ + 반사실 교정 랭킹 + 예상 향상폭 |
| `trainer/scripts/eval_pass_reference.py` | leave-one-out 자기정합성 검증 |

버킷 키는 `{수평|사선|수직}-{low|mid|high}-{±}{x|y}` 형태이며, **자세 레퍼런스가 확보되면
같은 키를 재사용한다.**

유사도는 `100·exp(−½·mean(σ²))`로 정의했다. 지표 하나를 버킷 중앙값으로 되돌린 반사실
유사도를 계산해 교정 **전에** 예상 향상폭을 낸다. 예측 Δ와 실측 Δ의 일치를 테스트로 고정했다.

### 11.2 검증

레벨10, 6인, 16,468패스. leave-one-out(5인 레퍼런스로 나머지 1인 채점):

| 제외 | 패스 | 버킷매칭 | 유사도 p50 | >2σ | >3σ |
|---|---|---|---|---|---|
| 김경호 | 1,600 | 99.9% | 72.2 | 15.9% | 5.1% |
| 손영석 | 3,887 | 99.9% | 73.2 | 6.7% | 1.9% |
| 임채원 | 2,523 | 100.0% | 76.6 | 6.0% | 1.3% |
| 전형기 | 2,987 | 99.8% | 72.4 | 11.9% | 4.7% |
| 정희록 | 2,961 | 99.1% | 71.7 | 12.8% | 3.9% |
| 최연진 | 2,536 | 99.8% | 75.2 | 14.7% | 4.2% |

버킷 키가 작업자를 넘어 일반화되고(매칭 99%+) 유사도 중앙값이 6인 균질하다. **임계는 이
분포에서 역산한다** — 3σ(숙련자 1.3~5.1%)를 교정 필요, 2σ(6.0~15.9%)를 주의로 둔다.
먼저 임계를 정하고 적용하는 순서는 쓰지 않는다.

`pytest trainer mcp_servers` 260 passed. 신규 테스트 26개.

**주의**: 패스 분할 초기 구현에 스트로크 끝 정지로 생기는 평탄부에서 반환점을 놓치는 버그가
있었다. 수정 전후로 전형기 레벨10 이탈 RMS p50이 12.8 → **21.7mm**, 45.8mm 임계 자기
불합격률이 22.2% → **28.6%** 로 바뀌었다. 이 문서와 외부 보고의 수치는 수정 후 값이 정본이다.

### 11.3 자세 코칭 — 차단 확정과 정확한 요청

관절 회전은 있으나 **관절 위치가 없다.** CSV의 관절 Position 컬럼은 전부 상수이며
(`bind_pose_local_pos_m`, 즉 바인드 포즈 로컬 오프셋) 월드 좌표가 아니다.

FK로 우회할 수 없음을 실측으로 확인했다.

- 오일러 순서 6종 × 곱셈방향 2 × 부호 2 = 24조합 전부 손–건 거리 **4.5~5.1m**
- 강체 정합(Kabsch) 후에도 잔차 **0.485m**, 조합 간 차이 0.18m로 **판별 불가**
- 원인: `Pelvis` Position이 월드가 아니다. 카메라·건은 상호 상관 Y 0.92 / Z 0.97,
  거리 중앙값 0.49m(팔 길이)로 정상적인 월드 좌표인데, Pelvis는 카메라와 상관
  X 0.63 / Y −0.28 / Z −0.14이고 평균 Z가 −0.19m다. → REQ-14

회전 공간 직접 비교도 성립하지 않는다. 버킷(방향×높이×진행부호)을 잡고 작업자별로 나눈 뒤
회전행렬 Fréchet 평균 대비 **측지 편차**를 재면 p50 **24~28°**, p75 38~48°다. 2σ가 50°를
넘어 코칭 임계로 쓸 수 없다. (오일러 산술평균의 wraparound 아티팩트가 아님을 측지거리
재측정으로 확인했다.)

> **요청: 관절 20개의 월드 좌표(Position)를 카메라·스프레이건과 동일한 좌표계로 export.**

이미 건 4종과 카메라를 월드로 내보내고 있어 추가 비용이 작다. 이 하나가 REQ-05
(`rotation.order`), REQ-08 (`hierarchy`), REQ-14(rig root 월드 변환)를 **전부 대체**한다 —
FK를 하지 않으므로 규약이 필요 없어진다.

수령 시 열리는 것: 관절별 σ 점수(MPJPE 기반), 특정 관절 교정, 반사실 계산에 의한 교정 전
예상 향상폭, 교정 후 실측 대조. 인터페이스는 §11.1 버킷 키와 반사실 랭킹을 그대로 쓴다.
