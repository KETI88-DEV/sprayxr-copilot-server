**Date**: 2026-08-28
**Status**: Draft (design) — 구현 전
**Scope**: 두 작업 동작을 정렬해 나란히 놓고, 자세 유사도와 관절별 이탈을 보이고, 교정문과 교정 후 예상 자세를 내고, 개선율을 재는 로컬 웹 프로그램. MCP·에이전트에 적용하기 **전에** 어떤 지표가 유효한지 눈으로 판정하는 것이 목적이다.

## 1. 목표 / 비목표

### 목표

- **의도가 같은 두 동작만 견준다.** 오른쪽 블록을 우상향으로 칠한 동작과 우하향으로 칠한 동작이 같은 것으로 취급되지 않는다.
- **정렬 후에 오차를 낸다.** 대응 없는 두 시계열의 차이는 오차가 아니다.
- **근거가 실측인 지표와 IK 산출물인 지표를 분리해 병기한다.** 어느 쪽이 70% 목표를 낼 수 있는지 판정할 근거를 만든다.
- 화면 하나에서 유사도, 관절별 이탈 강도, 교정문, 교정 후 예상 자세, 개선율을 모두 본다.

### 비목표

- **MCP·에이전트 연동.** 이 프로그램은 그 앞 단계다. 판정이 끝난 뒤 `pose_estimation` 라우터에 반영한다.
- **훈련생 실데이터.** REQ-16은 미확보다. 타 작업자 5인을 대용으로 쓰되 그들이 훈련생이라고 주장하지 않는다.
- **전신 IK 재구성.** 시뮬레이터의 IK 솔버가 없다. 교정 후 자세는 팔만 재구성한다(§6.2).
- **각도 교정 지시의 유효화.** REQ-19 `correction_target_gate`는 그대로 유효하며 이 프로그램이 그 게이트를 대체하지 않는다. 이 프로그램은 게이트를 **측정할 수 있게** 만든다.

## 2. 배경 — 실측으로 확인된 것

### 2.1 추적점은 3개이고 나머지 관절은 IK 산출물이다

시뮬레이터는 HMD + 양손 컨트롤러의 3점 추적이다. CSV의 관절 20개는 그 3점에서 IK로 푼 값이다.

데이터가 이를 뒷받침한다. `dataset_spec.md` §4.2의 측지 점프 발생률은 3-DOF 볼조인트에만 나타나고 1-DOF 힌지는 깨끗하다.

| 관절 | 자유도 | 점프 발생률 |
|---|---|---|
| RightUpperArm | 3-DOF | 1.84% |
| RightShoulder | 3-DOF | 1.36% |
| RightHand | 3-DOF | 1.09% |
| RightForeArm | **1-DOF** | **0.14%** |

이것은 IK 폴 벡터 플립의 지문이다. 손과 어깨의 거리로 팔꿈치 굽힘각(힌지)은 결정되지만 그 축을 도는 팔의 회전은 미결정이라 뒤집힌다. median 필터로 제거되지 않았던 이유도 이것이다. 데이터 결함이 아니라 IK 산출물의 성질이다.

**따라서 관절 20개의 정보량은 20×3 DOF가 아니라 실측 3강체의 18 DOF 이하다.** 관절 공간에서 재는 유사도는 정보량을 부풀린 표현이다.

### 2.2 실측 3점은 CSV에 월드 좌표로 직접 들어 있다

`10_1000451_1.csv` 실측(std, 미터):

| 오브젝트 | 정체 | std X / Y / Z | 상호 거리 평균 |
|---|---|---|---|
| 카메라 | HMD = 머리 | 0.138 / 0.356 / 0.541 | — |
| 한길숏건 | 오른손 컨트롤러 = 건 | 0.223 / 0.547 / 0.473 | 머리↔건 0.483 m |
| 플래쉬 | 왼손 컨트롤러 | 0.142 / 0.366 / 0.470 | 머리↔왼손 0.304 m |
| 한길폴건·반도폴건 | 미사용(주차) | 0 / 0 / 0 | 좌표 `(-694.61, 701.29, 698.25)` |
| 반도숏건 | 미사용(고정) | 0 / 0 / 0 | 주차 좌표가 아닌 정상 위치에 정지 |

세 점의 상호 거리가 모두 인체 범위다. 미사용 건 판별은 좌표값이 아니라 **분산**으로 해야 한다 — 반도숏건은 정상처럼 보이는 위치에 std=0으로 고정된다.

이 사실의 파급이 크다. 실측 3점과 착탄점(Ray)이 **같은 월드 좌표계**에 있으므로 채점 경로에서 다음이 모두 무관해진다.

| 요구사항 | 내용 | 채점 경로에서 |
|---|---|---|
| REQ-14 | 스켈레톤 리그와 월드의 좌표계 분리 | 무관 — 3점은 월드에 있다 |
| REQ-05 / REQ-08 | 회전순서 / 계층 | 무관 — FK를 돌지 않는다 |
| REQ-18 | 5인 CSV의 오일러 FK 대체 기각 | 무관 — 회전을 쓰지 않는다 |
| REQ-17 | BVH 프레임별 시뮬레이터 시간 | 무관 — BVH를 쓰지 않는다 |

**6인 605세션이 채점에 즉시 사용 가능하다.** 다만 표시용 전신 스켈레톤에는 여전히 FK가 필요하다(§2.3).

이상치가 있다. |머리−건| 최대 4.443 m(건을 내려놓은 프레임), |머리−왼손| 최소 0.000 m(겹침). 마스킹 규칙을 §5.4에 고정한다.

### 2.3 CSV는 자기 리그 데이터를 스스로 갖고 있다

`dataset_spec.md` §3이 기록한 대로 관절 `Position` 컬럼은 프레임 불변 상수(bind offset)다. 20개 관절 전수 확인 결과 `Pelvis`만 이동한다.

REQ-18의 CSV-FK 검정은 **BVH가 준 계층·본 길이·회전순서를 CSV 오일러에 적용**했다. 두 리그를 섞은 것이다.

| | 뼈 방향 축 | 좌우 구분 축 | Calf 길이 | Foot 길이 |
|---|---|---|---|---|
| CSV bind offset | −X | Z (±0.0284, ±0.0965) | 0.4223 | 0.4110 |
| BVH OFFSET | +Z | X (±0.082) | 0.4437 | 0.4453 |

축 규약이 다르고 뼈 길이가 5% 어긋난다. 69.7 mm 오차와 "순위가 얕아 규약이 특정되지 않는다"는 증상이 이것으로 설명된다.

**CSV 자체 bind offset + CSV 오일러 + ZXY로 FK를 도는 경로는 아직 시험된 적이 없다.** 회전순서는 BVH가 `Zrotation Xrotation Yrotation`을 65개 관절 전부에 균일 선언했고 이는 Unity의 기본 오일러 순서와 일치한다. 같은 시뮬레이터의 두 export이므로 CSV도 ZXY일 가능성이 높다.

이 경로는 **표시 전용**이다. 채점은 §2.2의 실측 3점에서 하므로 FK가 틀려도 지표가 오염되지 않는다. 검증은 §9에 둔다.

### 2.4 현행 버킷은 반대 방향 동작을 같은 것으로 취급한다

`pass_segmentation.py:207`:

```python
elevation = math.degrees(math.asin(min(1.0, abs(axis[2]))))
```

`abs`가 수직 성분의 부호를 버린다. `heading`은 수평 변위(x, y)에서만 나온다. 따라서 우상향 대각과 우하향 대각이 같은 버킷 `diagonal-mid-right`에 들어간다.

또한 버킷 3축(기울기·높이대·진행방향) 어디에도 **작업자 기준 착탄점의 좌우 위치**가 없다. 몸 정면에서 하는 스트로크와 오른쪽으로 팔을 뻗어 하는 스트로크가 같은 버킷이다.

이 두 결함은 의도가 다른 동작을 한 분포에 섞는다. 버킷 내 산포 s가 부풀려지고, `s/e ≈ 1.04`(REQ-19 baseline)의 원인 중 하나일 수 있다.

## 3. 핵심 결정

### D1. 채점을 두 축으로 나누어 병기한다

한 패스에 대해 두 지표를 동시에 계산해 화면에 나란히 놓는다.

- **실측 축** — 머리·양손 3점의 스트로크 프레임 좌표. 근거가 측정값이다.
- **관절 축** — 관절별 σ. 근거가 IK 산출물이다.

어느 쪽이 개선율 70%를 낼 수 있는지 지금 아무도 모른다. 하나를 골라 계약으로 굳히기 전에 실제 패스를 넘겨 보고 판정한다. 판정이 서면 한쪽을 버린다.

관절 축은 화면에 **"IK 산출물"이라고 명시**한다. 두 축이 크게 다른 값을 내면 그것은 작업자 차이가 아니라 IK 솔버 거동일 수 있고, 그 판별이 이 프로그램의 산출물이다.

### D2. 정렬 신호는 자세에 외생적이어야 한다

`dataset_spec.md` §5.1의 경고를 따른다. 자세 특징 위에서 DTW를 돌리면 DTW가 보고할 거리를 스스로 최소화해 낙관 편향이 생기고, "이 순간 팔꿈치가 틀렸다"는 교정 의미론이 무너진다.

정렬 변수는 **착탄점 궤적의 정규화 호길이 `s ∈ [0,1]`**로 한다. 시간 위상을 쓰지 않는 이유는 두 사람의 스트로크 속도가 다를 때 대응이 왜곡되기 때문이며, 속도 차이는 지워야 할 잡음이 아니라 보고해야 할 오차이기 때문이다. 호길이로 정렬하면 속도가 독립된 오차 축으로 분리된다.

### D3. 매칭 실패는 비교하지 않는다

질의 패스의 키에 해당하는 레퍼런스가 없으면 `unavailable`로 세고 평균에서 뺀다. 억지로 가까운 버킷에 붙이면 의도 차이가 오차로 보고된다.

키를 4축으로 늘리면 버킷당 표본이 준다. 이는 감수하는 대가다. 표본을 늘리려고 다른 동작을 섞는 것이 현재 `s/e ≈ 1`의 원인일 수 있기 때문이다. **버킷별 n을 항상 화면에 함께 표시**해 이 대가를 눈에 보이게 한다.

### D4. 판정 기준을 미리 박고 프로그램이 그것을 재게 한다

REQ-19 `correction_target_gate`(`s/e < 0.5`이면 각도 출력, 이상이면 관절 지목까지만)는 그대로 유효하다. 이 프로그램은 두 축 각각에 대해 `s`와 `e`를 산출해 게이트 판정을 화면에 표시한다. 게이트를 옮기지 않는다.

### D5. 기존 버킷 키 이름공간을 건드리지 않는다

`pass_segmentation.bucket_key`의 소비자는 `build_pass_reference`, `pass_coaching`, `build_pose_reference`다. 키 문자열이 바뀌면 기존 레퍼런스 아티팩트가 조용히 무효화된다.

`body_bucket_key`가 월드 기준 키와 문자열 공간을 분리했던 방식을 따라 **신규 키를 별도 이름공간에 두고 기존 키·기존 함수는 수정하지 않는다.**

## 4. 동작 동일성 판정

"같은 목적 동작"을 4축 키로 정의한다.

| 축 | 값 | 출처 | 상태 |
|---|---|---|---|
| ① 스트로크 기울기 | `horizontal` / `diag_up` / `diag_down` / `vertical_up` / `vertical_down` | 착탄점 변위 + 부호 복원 | 기존 수정 |
| ② 진행 방향 | 작업자 기준 `forward` / `back` / `left` / `right` / `none` | 머리 요 기준 수평 변위 | 기존 유지 |
| ③ 대상 지점 | 착탄점 UV의 격자 셀 | `Ray Texture UV X/Y` | 신규 |
| ④ 몸 기준 착탄 위치 | `left`/`center`/`right` × `near`/`far` × 높이대 | 머리 기준 좌표계의 착탄점 | 신규 |

### 4.1 ① 기울기 부호 복원

주축 `axis`의 부호는 PCA 고유벡터라 임의다. 부호는 주축이 아니라 **변위** `segment[-1] - segment[0]`의 수직 성분에서 가져온다.

- `horizontal`(고도각 ≤20°): 부호를 나누지 않는다. 방향이 ②에 이미 담긴다.
- `diagonal`(20~70°): 수직 변위 부호로 `diag_up` / `diag_down`을 나눈다.
- `vertical`(≥70°): ②의 수평 진행이 정의되지 않으므로 `vertical_up` / `vertical_down`으로 나누고 ②를 `none`으로 둔다.

### 4.2 ③ UV 격자

학습모드는 레벨당 맵이 1개라 `Ray Texture Map Number`로는 구역이 하나다(`dataset_spec.md` §5.2). region 라벨은 미저작이고 자체 공수가 필요하다(REQ-06).

따라서 **이름 붙은 구역 대신 UV 격자 셀을 직접 쓴다.** 저작 공수 없이 "같은 면의 같은 구획"을 판정할 수 있고, region이 나중에 저작되면 그 위에 얹는다. 격자 크기는 파라미터(기본 8×8)이며 패스의 UV 중앙값이 속한 셀로 정한다.

### 4.3 ④ 몸 기준 착탄 위치

머리 위치와 요(yaw)로 작업자 기준 좌표계를 세우고 착탄점을 그 안으로 옮긴다. 머리는 실측이므로 IK를 타지 않는다.

- 좌우: 몸 정면 기준 방위각 ±30°(파라미터) 안이면 `center`, 밖이면 `left` / `right`
- 거리: 수평 거리 임계(파라미터, 기본 0.8 m) 기준 `near` / `far`
- 높이대: 기존 `height_band`(low <0.6, mid <1.0, high) 재사용

## 5. 정렬과 오차 산출

### 5.1 리샘플

매칭된 두 패스를 각각 착탄점 궤적의 정규화 호길이로 파라미터화하고, `s`의 균등 격자 N점(파라미터, 기본 20)으로 리샘플한다. 격자점마다 두 패스의 상태가 1:1로 대응한다.

### 5.2 스트로크 프레임

각 `s`에서 원점을 그 순간의 착탄점에 두고 축을 잡는다.

- `n̂` — 벽 법선(건→착탄 방향의 벽 성분, 또는 착탄점 근방 궤적의 주평면 법선)
- `t̂` — 스트로크 진행 방향(호길이 접선)
- `û` — 수직(월드 Z를 `n̂`, `t̂`에 직교화)

이 안에서 머리·양손의 위치를 적으면 건을 벽에서 얼마나 띄웠는지, 진행 방향 대비 앞뒤 어디에 두었는지, 몸이 어디 있는지가 직접 읽힌다. 골반 기준을 쓰지 않는 이유는 골반이 IK 산출물이기 때문이다.

### 5.3 오차

정렬 격자 위에서 두 축을 각각 낸다.

- **실측 축**: 각 `s`에서 머리·오른손·왼손의 스트로크 프레임 좌표 차이. 시계열이므로 "스트로크 후반부에서 건이 벽에 붙는다" 같은 구간별 진단이 나온다.
- **관절 축**: 같은 `s` 격자에서 관절별 σ. 기존 `pose_similarity.joint_sigmas`를 재사용하되 가중치를 붙인다.
- **속도**: 정렬에서 분리된 독립 축으로 별도 보고한다.

### 5.4 프레임 마스킹

숫자를 보기 전에 고정한다(`dataset_spec.md` §4.4의 원칙).

| 조건 | 처리 |
|---|---|
| 활성 건 판별 | 세션 내 위치 분산 최대인 건. 좌표값으로 판별하지 않는다 |
| \|머리−오른손\| > 1.0 m 또는 < 0.1 m | 프레임 제외(건을 내려놓음 / 이상치) |
| \|머리−왼손\| > 1.0 m 또는 < 0.05 m | 왼손 지표만 제외, 다른 지표는 유지 |
| Ray 미적중 | 짧은 구간(≤ N프레임, 파라미터)은 보간 포함, 긴 구간은 패스 경계로 취급하고 조준 실패로 별도 집계 |
| 패스 길이 < 50 mm | 기존 `MIN_PASS_LENGTH_MM` 유지 |

## 6. 교정과 예상 자세

### 6.1 교정문

두 형태로 낸다.

- **실측 기반**: "오른손을 벽에서 5 cm 더 띄우고 15 cm 올리세요" — 작업자가 그대로 따를 수 있고 근거와 지시가 일치한다.
- **관절 지목**: "오른쪽 팔꿈치가 통상 범위를 벗어났습니다" — `ai_copilot_response_contract.md` §3.6에 따라 **각도는 붙이지 않는다.** REQ-19 게이트를 통과하기 전까지 관절 지목까지만 유효하다.

### 6.2 교정 후 예상 자세

- **실측 축**: 손·머리를 목표 위치로 옮긴 뒤 팔만 2-bone 해석적 IK로 재구성한다. 시뮬레이터의 IK 솔버가 없으므로 전신 재구성은 불가능하다. **재구성한 부분과 그대로 둔 부분을 화면에서 다르게 칠해** 어디까지가 근거 있는 그림인지 드러낸다.
- **관절 축**: `pose_similarity.apply_corrections`를 쓰되 **뼈 길이 보존을 요구사항으로 박는다.** 관절을 목표 위치로 그냥 옮기면 골격이 늘어나 물리적으로 불가능한 자세가 나온다(`27edfc1`에서 더미 주입 경로에 같은 성질의 결함이 있었다). 방향만 목표로 돌리고 길이는 유지하는 투영으로 한다.

### 6.3 개선율

지표는 기존 `pose_similarity.gap_closure` `G = (S1−S0)/(1−S0)`를 두 축 각각에 적용한다. 이미 기준에 가까운 패스는 분모가 작아 요동치므로 `MAX_ELIGIBLE_BEFORE` 필터를 유지한다.

**레퍼런스 분리를 강제한다.** 교정에 쓴 분포로 다시 채점하면 향상이 자동 보장되므로, 교정 레퍼런스와 채점 레퍼런스를 겹치지 않는 날짜에서 만든다(`eval_pose_correction.py`의 기존 규약). 화면에는 분리 채점과 동일 채점을 **둘 다** 표시해 격차가 얼마인지 보이게 한다.

`goal_year2.md`의 문구는 목표 자세를 입력으로 주므로 동일 채점에 해당한다. 두 값을 병기하는 이유는 납품 기준을 만족시키면서 그 값이 자기충족에 얼마나 기대는지도 함께 드러내기 위함이다.

## 7. 가중치

두 축의 가중치 근거가 서로 다르다. 둘 다 파라미터로 노출한다.

| 축 | 가중 | 근거 |
|---|---|---|
| 실측 | 오른손 > 머리 > 왼손 | 오른손이 건이고 도막 품질을 직접 결정한다. 왼손은 플래시라 작업 결과와 인과가 약하다 |
| 관절 | 오른팔 체인(Shoulder/UpperArm/ForeArm/Hand) 높게, 나머지 현저히 낮게 | 나머지 관절은 IK 합성값이라 신뢰도가 낮다 |

`goal_year2.md`의 "6개 이하의 주요 관절"은 제약이 아니라 이 가중치의 근거다. 상한을 채우려 하지 않는다.

trainer/scripts/

### 8.1 화면

한 화면에 다음을 놓는다.

1. 좌우 병치 3D 스켈레톤 — 질의 패스 / 레퍼런스. `s` 슬라이더로 동기 이동
2. 관절별 이탈 강도를 색으로 — 스켈레톤 위 착색 + 옆에 관절별 막대
3. 유사도 두 축, 버킷 키, 버킷 n, REQ-19 게이트 판정
4. 교정문 두 형태
5. 교정 후 예상 자세(재구성 부분 구분 착색) + 개선율 두 축, 분리/동일 채점 병기
6. 파라미터 패널 — UV 격자, 좌우 경계각, 거리 임계, 리샘플 N, 가중치
