# TSB 회차별 Height·누적 보정·리포트 계약

갱신일: 2026-10-21. 사용자가 전달한 TSB 옥재은 선임의 회신을 기록한 **계산·데이터 계약**이다. 2026-10-19의 ‘Dead Volume 수식·값 미확인’과 ‘모든 Height를 같은 누적으로 취급’한 가정을 정정한다. 아래는 제공처가 확인한 계산 규칙이며, 새 구현의 적용 범위는 마지막 절과 [엔진 계약](ENGINE_CONTRACT_KR.md)을 따른다. 기존 연구의 과거 라벨·점수를 자동 변경하는 문서가 아니다.

## 자료 단위

| 자료 | 실제 의미 | 처리 |
|---|---|---|
| 세션 `{모델}_{WorkID}_{회차}` | 한 회차의 수행. 1·2회차는 별도 세션 | 모델/WorkID로 회차 계보를 연결하되 세션을 합치지 않음 |
| `sessions/complete`의 한 면 Height | 해당 면·현재 회차분만 저장한 보정 전 두께 | 2회차면 같은 면의 1·2회차 원본을 픽셀 단위로 합산 |
| `cur_sequence_heatmap` | 이전 회차까지 포함한 보정 전 누적 두께 | 이전 회차 Height를 다시 더하지 않음. 같은 관측의 후속 revision도 덧셈이 아니라 교체 |
| `avg_thickness_um` | 모든 면과 현재까지 회차를 반영한 보정·집계 결과 | 세션 공식 평균으로 그대로 사용. Zone 평균으로 해석하지 않음 |

다른 면의 같은 이미지 좌표를 서로 더하는 것이 아니다. **면별로 정렬된 같은 픽셀의 회차를 합산**한 뒤 전 면의 대상 픽셀을 합쳐 집계한다. 회차 누락·면/모델/작업 계보 불일치·해상도 불일치를 보간으로 숨기지 않는다. 향후 Zone 완료 API가 둘 중 어느 Height 형식을 쓰는지는 그 API의 최종 계약에서 명시한다.

내부 연결에서는 출처 namespace·제공자 모델 표기·WorkID를 회차 family로 묶고, 면별 family에 map_num을 추가한다. **round는 개별 기록의 키와 정렬 항목이며, 서로 합칠 family 키에는 넣지 않는다.** 세션 ID의 제공자 모델 표기를 Zone 마스크의 geometry model_key와 같은 것으로 자동 간주하지 않고 명시적인 대응을 사용한다. 이 내부 필드명은 구현 제안이며 제공자 wire 필드명이 아니다.

## 제공자 확정 수식

1. 원본 디코딩: `t_raw = (R/255 + G/65025) × 20000`µm.
2. 면별 회차 합산: `t_sum = sum(t_raw_round1 ... current_round)`.
3. `t_corrected = t_sum - 10`µm. **회차 수와 무관하게 한 번만 차감**한다.
4. 상한: `min(t_corrected, 1600)`µm.
5. 보정 두께가 **1µm 미만**이면 유효 도포가 아닌 미도장으로 처리한다. 정확히 1µm는 유효하다.
6. 공식 리포트는 정확한 **작업 대상 영역** 안의 픽셀만 사용한다.

예를 들어 같은 픽셀의 1회차 raw160·2회차 raw170이면 누적330−10=320µm이다. 회차별로10을 빼서150+160=310µm로 만들지 않는다. 시퀀스 누적값330에는 과거 회차160을 재가산하지 않는다.

현재 RG16/B8의 B는 원본 도포 정보다. 보정 후 유효 픽셀은 추가로 t≥1 조건을 만족해야 한다. 과거 자료는 실제 B가 모두0인 형식이 있어 현행 B>0 지원 조건을 소급하지 않는다. 과거값의10µm·160/320 설정 확인과 과거 PNG의 지원/회차 계보 확인은 별개다.

## 평균·미도장 분모

- 제공자 진행률 **100% 이상**: 작업 대상 안의 유효 도포 픽셀 평균.
- 진행률 **100% 미만**: 작업 대상 안의 유효 두께 합 / 작업 대상 전체 픽셀 수. 미도장을0으로 포함한다.
- 무도포이면서 progress≥100 같은 모순 입력의 평균/오류 동작은 회신에 정의되지 않았으므로 임의로 제공자 결과를 만들지 않는다.
- 화면/입력 API에서 진행률이0~1인지0~100인지 단위를 추측하지 않는다. 제공자 수식의100%를 명시적 정규화 규약과 연결해야 한다.

현재 전송에는 정확한 작업 대상 마스크가 없으므로 **Height만으로 공식 리포트 전체 재현을 보장하지 않는다.** 도포 픽셀의 합집합, base alpha, Zone 컬러맵 전체의 합집합을 작업 대상 마스크로 자동 대체하지 않는다. Zone 마스크는 구역 구분 근거이며 작업 대상으로 선택된 영역과 같은지 별도 근거가 필요하다.

사용자가 선택한 **Zone 대표 등급=유효 도포부 평균**, **미도장률 별도** 정책은 유지한다. 이는 진행률에 따라 분모를 바꾸는 TSB의 세션 리포트 평균과 별도의 지표다. 보정 전 평균·보정 후 유효 평균·공식 세션 평균의 이름과 출처를 구분한다.

## 6구간과 3분류

각 구간은 보정 후 두께 t와 해당 회차의 누적 목표 DFT를 사용한다.

| 구간 | 경계 | 기존 3분류와의 대응 |
|---|---|---|
| 1 | t < 0.9DFT | 저도막 |
| 2 | 0.9DFT ≤ t < DFT | 저도막 |
| 3 | DFT ≤ t < 1.5DFT | 정상도막 |
| 4 | 1.5DFT ≤ t < 2DFT | 과도막 |
| 5 | 2DFT ≤ t < 2.5DFT | 과도막 |
| 6 | t ≥ 2.5DFT | 과도막 |

제공자 분포에서는 진행률100% 미만일 때 작업 대상 미도장도1구간에 포함한다. 우리의 도포부 한정 분포와는 분모가 다르므로 별도 필드로 관리해야 한다. 작업 대상 마스크가 없으면 그 공식 분포를 완전한 것으로 만들 수 없다.

## 적용 범위와 과거 연구

- 한화오션 과거 전문가 장비의 고정 설정: DeadVolume10µm, 1회차 목표160µm, 2회차 누적목표320µm. 이는 이번에 제공자가 과거 자료에도 적용하도록 확인한 사실이다.
- 따라서 과거자료의 보정 후 정상 범위는 1회차[160,240), 2회차[320,480)다. 과거 고정160..240 inclusive raw 라벨과 다르다.
- 현재 SW에서 확인했던156기본값이나 세션시작 사용자 지정값을 없애는 설명이 아니다. 특히 TSB 사내 개발자 샘플은 한화오션 과거 전문가 설정과 구분하며 실제 목표를160으로 자동 채우지 않는다.
- 개발자 세션 `3_11000346_1`의 약10µm차이는 **이제 제공자가 DeadVolume 때문이라고 확인**했다. 다만 모든 자료에서 이미지 평균−10이 같은 집계 결과가 되는 것은 아니다.
- 과거 원시 PNG/GT/모델/고정 실험/현재 논문은 보존한다. 새 회차 계보와 픽셀 보정·유효성·마스크/분모를 적용한 **별도 라벨 버전**으로 새 실험을 설계해야 한다. 평균값만10을 빼거나, 2회차 목표만 바꿔 기존 점수를 새 기준 성능이라고 쓰지 않는다.

## 구현 상태

2026-10-19의 기존 Zone CPU 경로는 보정 전 raw 진단용이었다. 이번 `trainer.zone_engine` v2는 픽셀별 회차 합산, DeadVolume 10µm 1회 차감, 1600µm 상한, 1µm 유효 판정, 정확한 Zone 컬러 마스크와 6구간 분포를 구현했다. 과거 경로의 미구현 상태와 새 v2 구현을 구분한다.

다만 작업 대상 영역의 별도 마스크와 진행률에 따른 공식 분모가 항상 전달되는 것은 아니다. 사용자와 합의한 **Zone 도포부 평균**을 판정에 쓰고, `avg_thickness_um`은 제공처의 공식 세션 평균으로 별도 보존한다. 따라서 Zone 계산값으로 공식 리포트 평균을 재현했다고 주장하지 않는다. 기존 논문 수치·라벨과 새 보정 기준도 혼용하지 않는다.

이 문서는 제공처가 확인한 계산 규칙의 요약이다. 설치·API와 검증 범위는 [설치·인계 안내](README_KR.md)를 따른다.
