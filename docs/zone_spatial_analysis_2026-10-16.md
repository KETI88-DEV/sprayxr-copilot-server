# 선박도장 구역 공간 분석과 형상 매칭 기술 조사

작성일·기술 조사 기준일: **2026-10-16**. 대상은 선박도장 훈련 시뮬레이터의 새 메시에서 유사한 전문가 작업 구역을 찾고, 작업 순서와 자세를 추천하는 기능이다. 연결 문서: [구역 형상 기반 코파일럿 PRD](zone_similarity_copilot_prd.md).

**권고안은 구역의 기하 특징, 주변 구역 관계, 전문가 작업 사례를 결합하는 검색·추천 구조다.** vLLM은 검증된 분석 결과를 설명하고, 공간 계산과 추천 판정은 MCP 뒤의 전용 분석 서비스가 담당한다. 초기 평가는 zoneID가 붙은 외부 메시로 수행하고, 최종 제품은 라벨 없는 GLB·FBX·OBJ를 지원한다. 외부 테스트 메시는 현재 미확보다.

### 1.1 식별자와 좌표를 분리해야 하는 이유

PPT p.2는 번호가 **면 단위**로 부여되며 같은 번호가 다른 면에 존재한다고 명시한다. 원본 `zone_rects.csv`와 [ZoneReferenceCatalog](../trainer/zone_reference.py)도 `(model_key, map_num, zone_id)`를 키로 쓴다. 새 기능의 영속 식별자는 다음을 권고한다.

```text
asset_revision + scenario_id + model_key + map_num + zone_id
```

`zone_id`는 문자열 `"1"`, `"2"`처럼 보존한다. `"-1"`은 미판정이며 검색 후보가 아니다. 학습 원본의 `scenario_id=1..10`과 `Learn01..Learn10`은 [scenario_map.csv](../trainer/demo_api/assets/zone_reference/scenario_map.csv)의 대응이다. 기존 UI의 `TR-L01`과 원본 scenario 번호를 암묵적으로 동일시하지 말고 명시적인 매핑을 둔다. 임의 자산의 파일명을 레벨 ID로 사용하지 않는다.

| 좌표 | 원점·단위 | 허용되는 해석 |
|---|---|---|
| 라벨 PNG | 좌상단, 2048×2048픽셀 | 구역 마스크와 텍스처상의 위치 |
| 텍스처 UV | 좌하단, 보통 정규화 0~1 | 삼각형 코너와 연결해 모델 표면으로 역투영 |
| 전문가 CSV 착탄 UV | 기존 코드는 텍셀 좌표로 읽음 | 이미지 Y 반전 후 라벨 조회; 정규화 UV와 혼용 금지 |
| FBX 모델 좌표 | 자산별 노드·단위 변환 | 모델 내부 형상. 씬 배치는 별도 |
| 시뮬레이터 월드 좌표 | 기존 검증 변환 적용, Y-up | 전문가 자세와 표면의 관계. 바닥 높이는 별도 필요 |
| 표면 국소 좌표 | 접점·법선·접선·중력 | 다른 형상으로 동작을 옮길 때 사용할 기준 |

UV 직사각형의 겹침은 실제 3D 인접 관계가 아니다. `area_percent`는 **텍스처 면적 비율**이지 도장 면적(m²)이 아니다. 검정·투명 픽셀은 미지정이며, 색 보간으로 새 번호를 만들지 않는다.

## 2. 공간 분석 방법과 신뢰 범위

PPT p.5~7 및 p.10~17의 그림을 렌더링해 색을 팔레트와 대조했다. 학습 FBX는 기존 [level_mesh.py](../trainer/scripts/level_mesh.py)의 리더로 읽었다. 각 UV 삼각형 내부의 텍셀 중심을 무게중심 좌표로 3D에 옮기고, 같은 위치의 라벨 색으로 구역을 정했다. 실제 면적 가중치는 삼각형의 `3D 면적 / UV 면적`이다.

```text
픽셀 중심 (i+0.5, j+0.5)
→ u=(i+0.5)/N, v=1-(j+0.5)/N
→ UV 삼각형의 무게중심 가중치 b0,b1,b2
→ p=b0*p0+b1*p1+b2*p2
→ w=A3D/(AUV*N*N)
→ 구역 면적 합계 Σw, 면적 가중 중심 Σ(w*p)/Σw
```

기본 격자는 1024², 수렴 확인은 512²다. 라벨은 원본 2048²에서 최근접 픽셀로 조회했다. UV 삼각형이 중복되는 표본은 제외하며 UV 퇴화 삼각형은 역투영하지 않았다. 레벨 3과 9는 2048²에서도 다시 계산했다. 아래 표의 면적은 **마스크와 메시가 겹친 부분의 근사 면적**이며 완전한 정답 면적이나 도료 소요량이 아니다. 경계 픽셀·패딩·UV 버전 차이의 영향을 포함한다.

여기서 **일치율**은 `구역색 표본 중 정확히 하나의 유효 UV 삼각형에 속한 표본 비율`이다. 3D 형상 검색 정확도·IoU·전문가 평가 점수와 다르다. 레벨 9의 불일치 원인은 아직 특정하지 않았다. UV의 패딩, 자산 리비전 차이 등을 후보로 조사해야 한다.

`ZoneDATA/zone_feats.npz`는 64,098행의 15개 배열이다. 키는 `lv,u8,v8,d,psi,h,ya,ok,yaw,headv,hx,hz,hy,hdx,hdz`이며 `ok=false` 2,448행은 모두 레벨 2다. **zone_id, 메시 해시, 특징 추출기 이름·버전, 좌표 명세가 없다.** 이미 완성된 3D 임베딩 DB라고 간주할 수 없다. 생성 코드와 각 변수의 정의를 확보한 뒤 재사용 여부를 결정한다.

### 2.2 원본 간 의미 충돌

1. **레벨 2:** PPT p.5의 3D 그림은 빨강 1을 상부, 파랑 3을 하부로 표현하지만, 라벨을 현재 FBX에 투영하면 1의 모델 로컬 Z가 낮고 3이 높다. 월드 정렬도 미검증이다. [전문가 변환 코드](../trainer/expert_zone_mapping.py)에는 레벨 2의 `1↔3` 보정이 이미 있다. 이 보정을 모든 입력이나 라벨맵에 다시 적용하면 이중 보정이 된다. 원본 채널별 ID 규칙을 확인해야 한다.
2. **Unit1 재사용:** PPT p.16은 `Unit1_3,4,5,6,7`이 학습03과 같다고 적지만 그림은 학습02형이고, CSV는 Unit3~6을 Learn02, Unit7을 Unit1-7로 연결한다. 이 보고서는 실행 데이터인 CSV 매핑을 유지하고 PPT 설명의 정정을 요청한다.
3. **Unit4_1:** PPT p.20은 자격2 전체 모델이라고 설명하지만 CSV의 Unit25는 비어 있다. 자동으로 Exam2에 연결하지 않는다.
4. **자격·실전 적용 범위:** PPT에는 자격2의 44개 라벨이 있지만 README는 검정·실전에 zone 미적용이라고 적는다. 자산의 존재와 해당 실행 모드에서의 API 지원은 별개다. 실전 1·2와 Unit8·25~28은 현재 CSV에서 확정된 매핑이 없다.

## 3. 학습 레벨별 구역 위치와 형태

아래 87개 구역은 모두 `map_num=1`이다. 형태 이름은 원본 PPT 색상과 기하를 대조한 **검토용 해석**이며 TSB가 부여한 공식 부품명이 아니다. `좌/우`는 PPT의 도장면을 보는 대표 정면 그림 기준이다. 양면은 작업 접근 방향에 따라 달라지므로 필요하면 ‘한쪽/반대쪽’으로 표현했다.

중심 `(x̂,ŷ,ẑ)`는 레벨 전체 메시 AABB 안의 면적 가중 중심을 0~1로 정규화한 값이다. 레벨 2만 FBX 로컬 축이고 나머지는 기존 변환을 적용한 월드 축이다. `ŷ`는 0이 모델 하단, 1이 상단이며 작업자의 무릎·어깨 높이를 뜻하지 않는다. 중심은 복합·오목 구역의 빈 공간에 놓일 수 있어 분사 목표점으로 사용하면 안 된다. 표의 m²는 겹친 영역의 근사 면적이다.

## 5. 공간 표현과 추천에 필요한 정보

레벨 1과 8은 각각 하나의 평판·곡면 zone이다. 반면 레벨 6·7·10의 zone은 여러 방향의 면을 묶은 작업 단위다. 자격2 I면은 연속된 평판을 6개 작업 영역으로 나눈 것이다. 즉 **기하학적 부품, 연속 표면 패치, 작업 구역은 서로 다른 개념**이다. 부품 분할 모델의 출력을 그대로 zoneID로 확정하면 기존 번호 체계와 일치하지 않는다.

| 표현 층 | 저장할 항목 | 추천에서의 역할 |
|---|---|---|
| 면 패치 | 평면·곡면, 면적, 법선 분포, 곡률, 경계·구멍, OBB, 실제 크기 | 작은 표면의 기하 비교 |
| 작업 구역 | 패치 집합, 연결 성분, 상하·좌우 위치, 중력 상대 방향, 접근 가능한 면 | 도장 단위와 작업 높이·방향 비교 |
| 주변 관계 | 실제 공유 경계, 이면각, 오목/볼록, 위/아래, 차폐, 인접 구역의 형상 | 같은 평판이라도 천장·벽·협소부를 구별 |
| 전문가 사례 | 구역 키, 시퀀스 ID, 착탄 비율, 손잡이, 작업자 체격, 도막 결과, 자세 품질 | 유사한 형상에서 수행된 검증 가능한 동작 검색 |
| 작업 정책 | 허용 순서, 선행 조건, 완료 구역, 전이 빈도, 접근 가능성 | 현재 상황에 맞는 다음 구역 선택 |

검색은 단일 zone뿐 아니라 **패치→구역→작은 이웃 구역 묶음** 수준으로 비교해야 한다. 새 모델의 한 구역이 기존 두 구역을 합친 형태일 수 있다. 매칭 결과는 1:1만 강제하지 말고 1:N·N:1과 부분 일치, 미일치를 표현한다.

형상 정규화로 회전·크기의 영향을 줄인 특징과, 중력·실제 치수·설치 높이 같은 작업 조건은 따로 보존한다. 같은 판을 90도 돌렸을 때 기하 유사성은 유지될 수 있지만 벽면 작업과 천장 작업의 자세 추천은 달라져야 한다. 좌우 반사는 회전으로 흡수하지 않고 별도 표시한다. 기존 정렬에는 det<0 변환이 있으므로 법선은 역전치 변환과 winding을 일관되게 처리해야 한다.

특히 레벨 3·6·7은 대표 순서의 지지가 적다. 새 모델의 구역 번호를 기존 순서에 대입하는 방식은 부적절하다. 전문가의 **형태 간 선행 관계와 국소 전이**를 새로운 인접 그래프 위에서 평가하고, 승인된 작업 규칙·완료 상태·접근 경로를 함께 적용해야 한다. 여러 유효 순서를 허용하며 ‘유일한 정답 순서’로 채점하지 않는다.

자세 기준은 기존 생성기의 구역 내 착탄 비중 80% 이상 필터를 출발점으로 재사용할 수 있다. 이 필터가 도막 품질이나 인체공학적 적합성을 보증하지는 않는다. 거리·속도·각도 범위는 승인된 전문가 프로필과 작업 조건에서 가져오며 보고서에서 임의의 일반 수치를 만들지 않는다.

### 6.1 도입 가능성을 바꾸는 공개 조건

- **PartField:** 공식 [LICENSE §3.3](https://github.com/nv-tlabs/PartField/blob/373025dbd283bb44cc4a6dc78c99994dbc91de32/LICENSE)은 비상업적 연구·교육으로 사용을 제한한다. 공개 코드라는 이유로 상용 시뮬레이터에 바로 포함하지 않는다.
- **PartSAM:** 자체 코드는 MIT지만 현재 전체 추론 경로가 PartField 구성요소를 사용해 해당 제한을 따른다고 [공식 LICENSE.md](https://github.com/czvvd/PartSAM/blob/b16d3e8f1b7f1af100df4a9e61dcd4f1788045b5/LICENSE.md)가 명시한다. ‘MIT 모델’로 단순 분류하면 안 된다.
- **Sonata:** [공식 README](https://github.com/facebookresearch/sonata/blob/18c09ff8d713494f78a8213792262b910977a65d/README.md)는 코드 Apache-2.0, 가중치 CC-BY-NC-4.0을 구분한다.
- **MeshFM:** 확인한 리비전의 루트에서 명시적인 LICENSE 파일을 확인하지 못했다. 코드·가중치 다운로드 가능 여부와 제품에 넣을 수 있는 권리는 별도다.
- 연구 후보의 설치·추론·정확도 벤치마크는 이번 문서 작업에서 수행하지 않았다. Spark aarch64와 현재 Python 3.11 환경에서 CUDA 확장·메모리 사용을 재현해야 한다.

SAM 3D Objects는 단일 이미지에서 3D 형상·배치를 복원하는 모델이다. 이미 정확한 메시가 입력되는 본 과제의 형상 검색기를 대신하지 않는다. 생성·복원 모델로 숨은 면을 만들어낸 뒤 실측 기하처럼 쓰지 않는다. [공식 설명](https://github.com/facebookresearch/sam-3d-objects).

### 6.2 접근 방식 비교

| 접근 | 장점 | 주요 한계 | 판단 |
|---|---|---|---|
| 렌더 이미지와 VLM만으로 구역 설명·검색 | 시각 설명과 초기 주석 작성이 쉬움 | 차폐·뒷면·치수·법선·접근 가능성을 빠뜨릴 수 있음 | 주석 보조 |
| 기하 특징 + 구역 관계 + 전문가 사례 | 작은 데이터로 시작, 근거 추적, CPU 기준선, 기존 CSV 재사용 | 복합·새로운 형상은 특징 설계와 데이터 보강 필요 | **1차 제품 권고** |
| 사전학습 3D 특징 + 기하 재검증 | 복합 부품과 형상 간 대응의 표현력 기대 | 도메인 전이·라이선스·메모리·배포 재현성 검증 필요 | 기준선 대비 개선이 확인될 때 추가 |

권고 검색 흐름은 `기하·작업조건 필터 → 구역/부분 형상 Top-k 검색 → 기하 정합과 주변 관계 재평가 → 적용 가능성 판단 → 전문가 사례 전이`다. 평판처럼 대응이 유일하지 않은 경우 후보 여러 개를 유지하고, 낮은 잔차만으로 자세를 확정하지 않는다. 텍스트 RAG는 재료·작업 규칙을 보완하지만 수치 형상 검색을 대신하지 않는다.
